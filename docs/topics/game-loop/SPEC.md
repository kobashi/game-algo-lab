## 1. 学習目標

1. 1 フレームが **入力 → 更新 → 描画** の繰り返しであることを説明できる  
2. **可変 timestep**（そのフレームの実経過時間 dt で 1 回更新）と **固定 timestep**（固定 Δt を溜めて複数回更新）の違いを観察できる  
3. 重いフレームで固定 step が積み上がると **スパイラル・オブ・デス**（1 フレーム内の更新回数が膨らむ）が起きうることと、**最大ステップ数クランプ**の役割を説明できる  

---

## 2. なぜゲームで使うか

ゲームは「壁時計」と「シミュレーション時計」がずれる。フレーム落ち・PC 差・タブ復帰で dt が跳ねると、物理が爆発したり再生速度が変わったりする。ループの設計はその土台。

---

## 3. アルゴリズム概要

### 可変 timestep

```
loop:
  dt = now - last
  last = now
  update(world, dt)   // 1 回
  render(world)
```

### 固定 timestep（アキュムレータ）

```
loop:
  dt = now - last
  last = now
  acc += min(dt, maxFrame)   // 巨大 dt を抑える任意
  steps = 0
  while acc >= FIXED_DT and steps < MAX_STEPS:
    update(world, FIXED_DT)
    acc -= FIXED_DT
    steps++
  alpha = acc / FIXED_DT     // 描画補間用（v1 は表示のみ）
  render(world)              // v1 は補間なしでも可
```

- デモの「世界」: 1 次元の跳ねるボール（位置 y、速度 v、床で反射）  
- 重いフレームの模擬: 人工遅延 ms を足して dt を膨らませる。遅延は描画の間隔そのものも伸ばす（カクカクになるが進む速さは同じ）。「ときどき重い」は 5 フレームに 1 回だけ遅延をかける  
- 計算に使う 1 フレームの経過は決まった値（1000/60 ms ＋ 遅延）。同じ操作なら同じ結果。負荷ボールで実際に間隔が 1.5 倍を超えて伸びたときだけ実測を使う  
- 物理の定数は正規化座標（0〜1.15、床 = 1.0）に合わせる。重力 8（床まで約 0.45 秒、停止まで約 2.2 秒）。旧値 900 は動きが 0.15 秒で終わっていた  
- 負荷用ボールは**決定的**（全員同じ高さ・初速 0）。乱数は使わない

## 4. 画面と操作

### 可視化

- キャンバス: 横軸 = シミュレーション時間（3 秒分。右端で自動停止、「繰り返し」なら最初から）。縦 = 高さ  
- 主役の跡: 更新 1 回ごとの位置 = 小さい点、描画した位置 = 輪。可変 = 青、固定 = 緑  
- 正解の軌道: 同じ物理を 1 ms 刻みで計算した点線（切り替え可）  
- キャンバス左上に、そのフレームの実経過と更新回数  
- 負荷用ボールは床下の細い帯に無彩色で描く（描画オン/オフ可。計算は常に行う）  
- 並走比較: 左=可変 / 右=固定。同じ遅延で同時に進む  
- 停止時に結果数値（更新回数・平均 FPS・1バウンド目の最高点・停止までの時間）。前回と比較  
- タイムライン風ログ: 直近フレームの realDt / update 回数 / accumulator
- 用語注: フレーム・FPS・更新・描画・dt・realDt・可変/固定 timestep・FIXED_DT・アキュムレータ・MAX_STEPS・スパイラル・オブ・デス・人工遅延・重いフレーム・シミュレーション・負荷など。点線の語にホバー・フォーカス・タップで説明（`js/platform/glossary.js`、辞書は `glossary-terms.js`）。各ブロックで最初の 1 回だけ印を付ける

### 操作

| 操作 | 挙動 |
|------|------|
| 再生 | 実時間ループ（requestAnimationFrame 相当の setTimeout 連鎖 or rAF） |
| 1ステップ | 1 フレーム分を手動実行 |
| リセット | 位置・速度・統計クリア |
| モード | 可変 / 固定 |
| FIXED_DT | 1/30〜1/120 相当（ms）。0.1 ms 刻み。整数 Hz の周期に近い値（16.7 など）はその周期（1000/60）として扱う |
| 人工遅延 | 0〜80ms（重いフレーム模擬） |
| 遅延のかけ方 | 毎フレーム / ときどき重い（5 フレームに 1 回） |
| MAX_STEPS | 1〜16（スパイラル防止） |
| 再生速度 | 0.1〜1.0×（1.0＝等速）。フレームの間隔（基本＋遅延）を伸ばす |
| 負荷ボール数 | 1〜200 step 1（1=主役のみ）。実負荷。変更時はシミュレーションを初期化。FPS 15 未満が約2秒続くと半分に戻す |
| 負荷を描画 | 既定 on。オフでも計算負荷は残る |
| 可変と固定を並べる | 既定 off。左右で同時実行 |
| 軌跡（点と輪） | 既定 on。主役のみ |
| 正解の軌道 | 既定 on。点線 |
| 繰り返し | 3 秒分の右端で初期位置へ |

URL: `mode,dt,lag,spike,maxsteps,speed,balls,loop,trail,drawload,compare,ref`

## 5. 成功定義

- 可変: フレームごとに update 1 回、遅延を上げるとボールの挙動が粗くなる/跳ね方が変わる様子が分かる。遅延 0 では固定と同じ結果（最高点 0.399）、遅延 50 で 0.363 に下がり、跡が点線より低くなる  
- 固定: 遅延 0 / 50 / ときどき重い のどれでも最高点 0.399・停止 2233 ms  
- 固定: 遅延があっても物理の 1 ステップは FIXED_DT 固定。MAX_STEPS を下げると更新が追いつかずログに警告  
- C# サンプルに可変/固定の核を載せる
