音の計算は `js/audio/` を応用トピックと共有する。入門ページが学生に操作させるのは、イベント、OneShot、簡単な BGM、実験プレイの発行まで。

## 残す契約

入門の演習・課題・詳説が今の文面のまま成り立つように、次は変えない。

- 最初の画面に、Jump / Land / Hit / Pickup のボタン、イベント名の直接送信、ログ、模式図、ミュート、対象イベント、周波数・長さ・音量が見える。ゲームの出来事をまねる列と、イベント名を直接送る列は、同じイベントを発行する。それぞれの直前に、用途を 1 文で書く。
- イベント名は `Jump` `Land` `Hit` `Pickup` `UI`。購読側が `js/maps/sfx-events-config.js` の周波数と長さを既定にし、選択中のイベントだけを上書きする。
- ログの文は `Emit ${名前}`、`SE play ${freq}Hz ${dur}s g=${gain}`、`SE (muted) ${freq}Hz ${dur}s`、`SE (gain 0)`、`SE (no AudioContext)`。ミュート中も Emit は出る。
- `playTone(freq, dur, gain = 0.08)` は残す。音を鳴らす前に模式図を更新する。
- URL の `ev` `freq` `dur` `gain` はこれまでどおり。適用のあと、その値を選択中イベントの上書きとして保存する。
- 模式図は計算で描く。青が波形、黄が包絡線。実測の波形は別のキャンバスで、AnalyserNode の時間波形である。
- 発行側（ボタン、実験プレイ、自動の流れ）は音の関数を呼ばない。`emit` だけを呼ぶ。
- AudioContext は最初の操作で1つ作り、音のたびに作り直さない。ページを離れるときに閉じる。

## 学習目標

1. ゲームイベントを発行し、購読側がそれを受け取れる
2. イベントが起きたとき、OneShot の周波数・音量・長さを購読側で決められる
3. BGM を鳴らしながら効果音を重ねられる
4. 実験プレイはイベントを出すだけで、鳴らす音は購読側が決める
5. 無音でも、ログで発行と再生の判断を追える

発音数、ランダム化、バス、ダッキング、コンプレッサー、材質、移動、空間、ループ、拍、曲の切替、レイヤーは応用サウンドの各トピックで扱う。移管は [audio-course.md](../audio-course.md)。

## 画面

タブはない。最初の画面に、イベントボタン、直接 Emit、ログ、模式図、実測波形、ミュート、対象イベント、周波数・長さ・音量・波形、BGM の再生と音量とループ、実験プレイがある。

安全な発音数の上限と音量の制限は、画面の操作ではなく内部で維持する。画面にないキーは URL から落とす。残るキーは `ev` `freq` `dur` `gain` `wave` `bgmvol` `loop`。

### 実験プレイ

小さな横移動。ジャンプ、着地、敵への接触、コインはイベントだけを出す。キャンバスにフォーカスがあるとき、矢印と Space ではページをスクロールしない。

## 操作

| 操作 | 挙動 |
|------|------|
| Jump 等ボタン | 対応イベントを Emit → 購読者がトーン再生 |
| 対象イベント | 調整するイベントを選ぶ（config の既定は残す） |
| 周波数 / 長さ / 音量 | 選択中イベントの上書き。freq 80〜1200 を 0.1 Hz 刻み、dur 0.02〜0.5 step 0.01、gain 0〜0.3 step 0.01（既定 0.08） |
| 波形 | 模式図。実測は別 |
| BGM | 再生、一時停止、再開、停止。効果音と重ねる |
| ミュート | ボイスを作らずログのみ |
| 実装課題 | 新しいイベント名を入力し、`soundFor` がその名前に安全な音を返し、未登録の名前とは戻り値を分ける。スライダーだけでは完了しない。イベント名と関数は提出票と JSON に入る |

## 成功条件

- `?ev=Hit&freq=880` で Hit のログは 880 Hz、Jump は 440 Hz。ミュートでも `Emit Hit` と `SE (muted)` が出る。
- BGM を鳴らしながら OneShot を重ねられる。
- 実験プレイは `emit` だけで音を鳴らす。
- 実装課題は、学生が入力したイベント名と、書いた `soundFor` を見る。未登録の名前とは戻り値が違う。失敗の文に期待する周波数は書かない。
- 提出課題の URL A と B は、Jump、Land、Hit、Pickup、UI のどれか同じイベントで、周波数だけが違う。新しいイベント名と関数は提出票に入る。
- PC と狭い幅の両方で、ボタンと課題の入力が画面内に収まる。
