## 1. 学習目標

1. **MAX 節点**は自分（最大化）、**MIN 節点**は相手（最小化）と説明できる  
2. 葉の**局面評価値**を、親が max / min で吸い上げる流れを追える  
3. AND-OR の「真偽」が、Min-Max では「数値の優劣」に一般化されると説明できる  
4. 素の Min-Max は**全子を読む**（枝刈りは次の α-β）と理解できる  
5. 選ばれない枝の葉を変えても根の値が変わらないことがある、と観察できる  

---

## 2. なぜゲームで使うか

交互着手・完全情報のゲーム（将棋・オセロ等）で「相手も最善を取る前提」の読みの基本形。

---

## 3. アルゴリズム概要

```
Minimax(n, depthLeft):
  if n が葉: return n.score
  if depthLeft <= 0: return 0
  if n が MAX:
    v = -∞
    for c in children:
      v = max(v, Minimax(c, depthLeft - 1))
    return v
  if n が MIN:
    v = +∞
    for c in children:
      v = min(v, Minimax(c, depthLeft - 1))
    return v
```

- 探索順: 深さ優先・子は左から右  
- 本デモでは α-β 枝刈りは**しない**（深さ制限にかからない葉はすべて評価しうる）  
- 開始は `Minimax(根, 深さ制限)`。既定の制限 3 はこの木の葉の深さと同じなので、打ち切りは起きない（従来どおり全12葉を評価）  
- **打ち切り節点の評価は 0**。ヒューリスティックは持たせず、残りの深さが 0 になった非葉は葉の代わりに定数 0 を返す  

---

## 4. 画面と操作

- SVG ゲーム木: MAX / MIN / 葉、評価値、評価中ハイライト、最善枝  
- 再生 / 1ステップ / リセット、速度  
- 葉の評価値（カンマ区切りテキスト）  
- 深さ制限（1 / 2 / 3）  
- DS: コールスタック、確定した v  
- 共有: 「この設定のURLをコピー」  
- 繰り返し再生、葉クリックで評価 ±1、前回の根の値との比較、最善枝ハイライト  

リセットは探索状態だけを戻す。葉の値と深さ制限は維持する。

## 5. 初期データ

`js/maps/minimax-tree.js` — 深さ3・葉12の標準木（2026-07-19 改訂。旧版は深さ2で
MIN の下に再び MAX が現れる交互再帰が見えなかったため、根(MAX)→手(MIN)→応手(MAX)→葉
の3段構成にした。α-β・モンテカルロと同型・同値で直接比較できる）

config の葉スコアは既定値として残し、デモ側で上書きする（ファイルは書き換えない）。

既定の葉（左から DFS 順、12個）:

`5,3,7,9,4,2,1,3,6,8,7,4`

手計算（制限なし）: 手L=min(5,9)=5、手M=min(4,3)=3、手R=min(8,7)=7 → 根 max(5,3,7)=7（手 R）。

## 6. 調整パラメータ

| コントロール | 内容 |
|---|---|
| 葉の評価値 | テキスト。カンマ区切りで葉を左から順に指定 |
| 深さ制限 | select。`1` / `2` / `3`。既定 `3`＝制限なし（葉まで） |

- 葉の個数が12でない、または数値として読めない入力は**却下して警告**。clamp しない。木は既定に戻す  
- 深さ 2 では応手（MAX）で打ち切り、深さ 1 では手（MIN）で打ち切り。どちらも評価 0  
- URL: `leaves`（カンマ区切り）, `depth`
