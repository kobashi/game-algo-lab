### AUDIO-ADAPT-01（P1） 着地直前の速度が失われる

- **問題**　正解した実装でも、着地の強さを聞き比べられない。採点は速度 0 をほぼ無音にすることを求めるため、その条件を満たすほどデモで着地音が聞こえにくくなる。
- **再現**　総合演習で、速度 0 の着地をほぼ無音にし、速い着地ほど大きくする `landImpact` を書いて「この実装で聞く」。ジャンプして着地する。垂直速度の表示は 0 のまま、着地音はほとんど出ない。
- **原因**　シミュレーションが地面に触れたフレームで垂直速度を 0 にしたあと、試聴がその値を `landImpact` に渡している。[シミュレーション](../../js/audio/game-sim.js) · [試聴](../../js/audio-adaptive-lab.js)
- **推奨修正**　地面に触れる直前の垂直速度を着地イベントに渡し、採点と試聴を揃える。
- **修正後の確認**　正解した `landImpact` で、低いジャンプと高い着地の音量が聞き分けられる。速度 0 の採点条件は残る。入門の `Emit Land` はこれまでどおり。

### AUDIO-ADAPT-02（P2） 停止と表示された音が鳴り続ける

- **問題**　画面上の発音数と実際に聞こえる音がずれ、停止方針を耳で比較できない。
- **再現**　発音が 4 を超えるまで短い間隔で音を出す。ログは「停止」と出る。止めたはずの音は、最初に予約した終了時刻まで聞こえる。
- **原因**　`pickStop` が選んだ音は管理リストから外れるが、オシレーターは最初に予約された終了時刻まで再生される。[試聴](../../js/audio-adaptive-lab.js)
- **推奨修正**　選んだ音のオシレーターと関連ノードを、その時点で止める。画面の発音数は、聞こえている音と揃える。
- **修正後の確認**　停止ログの直後、その音は聞こえなくなる。表示の発音数は 4 を超えたまま残らない。

### AUDIO-TASK-01（P2） 保存が編集前の採点結果を出す

- **問題**　関数や設計文を直してから保存すると、編集前の点数や設計文が提出される。
- **再現**　一度「動作テスト」を押す。関数または設計文を書き換える。「動作テスト」を押し直さず「結果を JSON で保存」を押す。ダウンロードされる JSON は、書き換える前の結果である。
- **原因**　保存ボタンは、前回のテストで作った JSON を再利用する。[保存](../../js/audio/student-task.js)
- **推奨修正**　保存時に、画面にある今の入力を採点し、ダウンロードと画面の結果を揃える。
- **修正後の確認**　テストのあとで関数と設計文を直し、テストを押し直さずに保存する。JSON の点数・設計文と、画面の結果が、保存した時点の入力と一致する。読めない関数では、古い JSON を出さない。

### AUDIO-ADAPT-03（P2） 足音の秒と試聴の距離が一致しない

- **問題**　`stepInterval` の戻り値は秒と説明されているが、試聴は移動距離が `interval × 80` に達したときに鳴らす。`0.5` を返す関数でも、移動速度が 160 px/s なら約 0.25 秒ごとに鳴る。
- **再現**　`stepInterval` が常に `0.5` を返す関数で「この実装で聞く」。歩行速度で移動し、足音の間隔を計る。
- **原因**　教材文は秒を教え、試聴は戻り値を距離の係数に使っている。[説明](../../js/audio/topic-tasks.js) · [試聴](../../js/audio-adaptive-lab.js)
- **推奨修正**　秒を教える課題では、経過時間で発音を判定する。採点の「速いほど間隔が短い」は維持する。
- **修正後の確認**　`0.5` を返す関数の足音は、約 0.5 秒ごとになる。空中や遅すぎる移動で 0 を返す採点条件は残る。

## 対応（2026-11-21 · Grok Build）

ブランチ `grok/audio-adaptive-review`。audio-adaptive-lab は修正 0→1。成熟度コードは oneshot のまま。一発未調整の修正合計は 9→10。共通の保存を直しただけで、ほかのトピックの修正回数は変えていない。

### AUDIO-ADAPT-01

地面に触れたフレームは、垂直速度を 0 にする前の値を `landSpeed` として残し、`Land` の payload `{ speed }` と `landImpact` に渡す。画面の「着地直前」とログ `着地 275` は、その速度。次のフレームでは 0 に戻り、着地のたびに 1 回だけ渡す。

確認: Node のスモークで、地面に立っているだけでは Land が出ず、ジャンプの着地速度は 40 より大きく、その tick の `vy` は 0、次の tick の `landSpeed` は 0。ヘッドレス Chrome ではログと読み上げが `着地直前 275`。入門の実験プレイはログ `Emit Land` のまま（速度の数値は出ない）。

### AUDIO-ADAPT-02

発音は、終了時刻まで `stop` を予約しない。上限を超えたとき `pickStop(voices, "oldest")` が返した音は、音量を落としてから `stop` を 1 回だけ呼ぶ。自然に終わった音も、同じ経路で 1 回だけ止める。画面の発音数は、管理している音の数。

確認: 間隔 0.01 秒の関数で聞いたとき、ログに「を停止」が出て、読み上げの発音数は 4。ヘッドレス Chrome では、開始から 0.065 秒より前に `stop` された音が 42 あった。デモが渡す方針は `oldest`。quietest と reject の聞き比べは、動作テストの条件のまま。

### AUDIO-TASK-01

「結果を JSON で保存」は、毎回いまの関数と設計文で採点してから書き出す。画面の結果もその採点に置き換わる。関数を読めないときは JSON を出さない。

確認: 初期の関数で動作テストすると足音は 0。その後、秒を速度で短くする関数と 51 字の設計文に書き換えて保存した。JSON は足音 25、設計 10、設計文はその 51 字。画面の結果も同じ。動作テストは押し直していない。

`grok/sfx-events-review` も `student-task.js` を編集している。両方を統合するときは、入門の「提出票へ入れる」を残し、保存は毎回 `execute()` する。

### AUDIO-ADAPT-03

総合演習の試聴は、`stepInterval` の戻り値が 0 より大きいあいだ経過時間を足し、その秒に達したときに足音を 1 回鳴らす。課題文と「このデモで学ぶこと」に、戻り値は秒だと書いた。採点は、空中と遅すぎる移動は 0、速いほど間隔が短い、のまま。

確認: 常に `0.5` を返す関数で 1.1 秒歩くと、足音は 2 回。Motion Audio の観察デモは、ページの説明どおり移動距離で足音を出す。
