## 3. 横断的な課題（重要度順）

### C1【最重要】演習の課題文がサイト上に存在しない

- v0.16〜v0.19 で「調整課題」のための**道具**（スライダー、URL 共有、軌跡・速度・結果表などの観測表示）が整備されたが、
  **課題文そのもの**はどのページにも無い。ページ見出しは「このデモで学ぶこと」と「C# 実装例」だけである。
- 受講生は「何を変えて、何を見て、何が分かれば正解か」を自分で考えるしかない。
  自習用のコースとしては、ここが最大の欠落。
- 道具が揃っているため、**課題文を足すだけで効果が大きい**（コード改修は小さい）。

### C2 既定値のままでは要点の現象が起きないデモがある

- **game-loop**: 人工遅延の既定は 0 ms。この状態では可変と固定に差が出ず、要点（重いフレームで可変が不安定になる、固定は更新回数で吸収する）が見えない。
- **velocity-motion**: 既定は 1ステップ約 2 px（vx 120 px/s × 16.7 ms）で、障害物 24 px＋球の直径 24 px を飛び越せない。
  すり抜けを起こすには dt・速度を大きくし厚みを小さくする組み合わせが要り、手探りでは到達しにくい。
- どちらも**「この値にしてみよう」と指示する課題**か、**現象が起きるプリセット**で解決する。

### C3 コースの導線が途切れている

- 各ページ下部の「次へ」は、13本中 **12本すべてがコース外**のトピックを指す（最後の1本は該当なし）。
  例: game-loop の「次: 時間管理」、velocity-motion の「次: 加減速」。コースから入った受講生はここで脱線する。
- 「前段」表記もコース外を指す: sfx-events → イベントシステム、minimax → AND-OR、gfx-ui-canvas → 座標 など。
  コースから来た受講生には「前提を飛ばした」ように見える。
- トピックページには「入門コースの何本目か」の表示も無い。

### C4 「考えるAI」段の段差が大きい

- minimax（抽象的な木）の次が tic-tac-toe だが、tic-tac-toe の説明と操作は
  **α-β・メモ化（転置表）・対称性除去・モンテカルロ**を前提にしている（ページ内でそれぞれ3〜6回言及）。
  これらはコースに含まれていない。
- 結果として、コースの最終段が「知らない用語のトグルを押す」体験になりやすい。

### C5 minimax の深さ制限が誤った理解を招く

- 深さ制限で打ち切った節点の評価は **一律 0** である。標準木（深さ3）で制限を1や2にすると、
  打ち切りが根の全ての子に及ぶため、**根の値は常に 0 になり、どの手も同点**になる。
- 本来の学習点は「読み切れないときは**評価関数**で見積もる」ことだが、現状は「読めないと 0」という形でしか見えない。
- 対策: 打ち切り時に「評価関数で見積もる（例: 子の葉の平均）」を選べるようにするか、少なくとも
  「打ち切りでは本来、評価関数を使う。ここでは 0 に固定している」と明記する。

### C6 結果が実行ごとに変わり、課題の答え合わせがしにくい

- **accel-gravity** は再生時の時間刻みに実経過時間を使う（1/60 秒以上の経過で1歩、0.2 秒で上限）。
  最高点の数値が画面のフレームレートや負荷で変わるため、「2回目の最高点はいくつか」を課題にしても受講生ごとに値がずれる。
- game-loop は v0.19.0 で観測を決定的にした。一方、コースで直後に学ぶ accel-gravity が可変刻みなのは方針として不整合でもある
  （game-loop で「固定刻みが安定」と学んだ直後に、可変刻みのデモを見ることになる）。
- velocity-motion は dt スライダーの値で固定刻みなので問題ない。accel-gravity も同じ方式に揃えるのがよい。

### C7 振り返り・到達確認が無い

- コースページは段ごとに1行の説明とカードだけで、段の終わりに「ここまでで言えるようになったこと」の確認が無い。
- 所要時間の目安も無い。

### 段1 まず動かす

#### 1. game-loop — 可変 timestep と固定 timestep

**2026-09-27 改訂（Claude。§11）**: デモの物理と表示を直したので、手順と数値を差し替えた。旧版は 0.330 / 0.323 / 「—」。

- **目標**: 重いフレームで可変は結果が変わり、固定は更新回数で吸収することを説明できる。
- **予想**: 処理が重くなったとき、ボールの最高点は可変と固定でどう変わるか。
- **手順**:
  1. `game-loop.html?compare=1` で再生する（3 秒分で自動で止まる）。結果表の「最高点」と「更新回数」を記録し、キャンバスで青（可変）と緑（固定）の跡を見比べる。
  2. `game-loop.html?compare=1&lag=50` で同じことをする。動きを追えなければ、再生速度を下げるか「1フレーム」で送る。
  3. `game-loop.html?compare=1&lag=80&spike=1`（5 フレームに 1 回だけ重い）で同じことをする。
  4. `game-loop.html?mode=fixed&lag=80&maxsteps=2` で再生し、打ち切りの警告と、3 秒分にかかる時間を見る。
- **期待される観察**:
  1. 遅延 0 では、可変も固定も最高点 **0.399**、止まるまで **2233 ms**。跡は重なる。更新はどちらも 1 フレームにつき 1 回。
  2. `lag=50` では描画が 1 秒に 15 回になってカクカクするが、進む速さは同じ。固定は **0.399・2233 ms のまま**で、輪と輪の間に小さい点が **4 つ**並ぶ（1 フレームの更新 4 回）。可変は輪 1 つに点 1 つで、最高点 **0.363**、止まるまで **2067 ms**。青い跡が点線（正解）より低くなる。
  3. `spike=1` でも固定は同じ **0.399・2233 ms**。可変は重いフレームのところで跡が飛び、止まるまで **1797 ms** と早まる。
  4. `mode=fixed&lag=80&maxsteps=2` では毎フレーム「打ち切り」が出る。跡は変わらないが、3 秒分に **約 9 秒**かかる（シミュレーションが実時間より遅れる）。
  5. 固定も正解（最高点 0.432）とは少しずれる。1 回の更新が 16.7 ms と粗いから。大事なのは、遅延があっても同じ結果になること。
- **発展**: MAX_STEPS を無くすと何が起きるか（スパイラル・オブ・デス）。

#### 2. input-basics — held / down / up

- **目標**: 「押している間」と「押した瞬間」の違いを説明できる。
- **予想**: キーを1秒押し続けたとき、Jump と Fire はそれぞれ何回発生するか。
- **手順**: ページを開くとポーリングは既に動いている。キャンバスをクリックしてから、Space・Z・X を約 1 秒押し続ける。次に `input-basics.html?longms=1000` で、X を 1 秒未満と 1 秒超で押し比べる。
- **期待される観察**: Jump の DOWN は **1 回**（JumpCount=1）。Fire は押しているフレームごとに増える（約 1 秒で数十回。この環境では 39。正解は回数の一致ではなく、Jump が 1 回で Fire が増え続けること）。Charge は既定 400 ms を超えると **1 回**。閾値 1000 ms では 0.7 秒では 0 回、1.2 秒で 1 回（ログに `Charge LONG (≥1000ms)`）。
- **発展**: Fire を「押した瞬間だけ」に直すにはどの判定を使うか。

### 段2 物を動かす

#### 3. velocity-motion — 位置 ← 位置 ＋ 速度 × dt

- **目標**: 1ステップの移動量が障害物より大きいと、衝突を飛び越すことを説明できる。
- **予想**: dt を大きくしても、ボールは障害物で必ず跳ね返るか。
- **手順**:
  1. `velocity-motion.html?obs=1&trail=1` で既定のまま再生し、跳ね返ることを確認する。
  2. `velocity-motion.html?obs=1&trail=1&vx=220&vy=0&thick=8&dt=200` を開く。1 フレームの移動は **44.0 px**、厚みは **8 px**。再生または 1 ステップを 6 回進める。再生すると 1 歩の間隔も 200 ms になり、1 秒に 5 歩進む。
- **期待される観察**: 手順 1 の既定は移動約 **2.1 px**、厚み 24 px で、障害物に当たって反射する（20 ステップ以内にすり抜けない）。手順 2 は **6 ステップ目**に「すり抜けた — |v|·dt=44.0px が厚み 8px を超えた」。軌跡の間隔が障害物より広く、重ならないまま通り抜ける。再生では約 **1.3 秒**ですり抜ける。ボールの進む速さは dt=16.7 のときと同じで、1 歩が粗くなるだけ。
- **発展**: 物理・判定カテゴリの Swept AABB がこの問題をどう解くか。

#### 4. accel-gravity — 重力と反発

- **目標**: 重力が速度を毎フレーム変えること、反発係数が跳ねる高さを決めることを説明できる。
- **予想**: 反発係数 0.75 のとき、2回目の最高点は1回目の何倍になるか。
- **手順**: `accel-gravity.html?rest=0.75&trail=1` で再生し、最高点の表示（A → B → C）を記録する。次に `?rest=0.5` で同じことをする。
- **期待される観察**: 隣り合う最高点の比は、およそ反発係数の 2 乗（0.75 なら約 0.56、0.5 なら約 0.25）。再生も 1 ステップと同じ固定刻みで進むため、再生速度を変えても同じ数値になる。反発 0.5 の最高点は **73 → 16 → 4 → 1**（比は 0.22・0.25・0.25）。反発 0.75 は **166 → 88 → 49 → 26 → 14 → 7 → 3 → 1 → 0**（比はおよそ 0.53〜0.56）。（2026-09-26 P1-3 の固定刻み化のあとに実測。1 ステップ・再生 1.0×・0.5× で同じ列になることをローカルのブラウザで確認）
- **発展**: なぜ2乗になるのか（跳ね返り直後の速さと高さの関係）。

#### 5. circle-collision — 円同士・円と箱

- **目標**: 平方根を使わない接触判定と、箱への最近点を説明できる。
- **予想**: 半径 40 と 32 の円は、中心の距離がいくつで接触するか。
- **手順**: `circle-collision.html?ax=180&ay=160&bx=252&by=160&ar=40&br=32` を開く。次に矢印キーで円 B を右へ 3 px 動かす（同じ状態は `bx=255`）。
- **期待される観察**: 中心間距離 **72.0** で「ぎりぎり接触」（72² = 5184、半径の和も 72）。3 px 離すと距離 **75** で miss。距離の 2 乗と半径の和の 2 乗を比べれば平方根は要らない。
- **発展**: 円と箱では、中心を箱に Clamp した最近点までの距離で判定する。箱の角の近くで確かめる。

### 段3 手ざわりを作る

#### 6. coyote-time — 猶予時間

- **目標**: 数十ミリ秒の猶予が操作の失敗を減らすことを、回数で説明できる。
- **予想**: 猶予 0 ms と 120 ms で、崖から落ちながらのジャンプの成功回数はどれくらい違うか。

- **発展**: 猶予を 400 ms にすると何が不自然になるか。

#### 7. gfx-camera — カメラの追従

- **目標**: ワールド座標とカメラ座標が独立していること、デッドゾーンと追従係数の役割を説明できる。

#### 12. minimax — 先読み

- **目標**: MAX と MIN が交互に値を吸い上げ、葉の値が根の最善手を決めることを説明できる。
- **予想**: 手 R の下の葉を1つ下げると、根の値と最善手はどう変わるか。

  1. 既定のまま再生し、根の値と最善手を確認する（根 = 7、最善は手 R）。

## 11. game-loop の見え方の改善（Claude, 2026-09-27）

ユーザーの指摘: 教材の意図がわかりにくい。パラメーターを変えても、シミュレーション画面では見分けがつかない。

**原因**（コードと同じ式で計算して確認）

1. 重力 `gravity: 900` はピクセル単位向けの値で、座標は 0〜1.15 に正規化されていた。ボールは 3 フレーム（50 ms）で床に着き、150 ms で止まる。実験全体が一瞬で終わり、0.1× でも 1.5 秒しかない。遅延 50 ms では 1 フレーム目で床に着き、最高点が「—」になっていた。
2. 人工遅延は計算上の経過時間に足すだけで、描画は 1 秒 60 回のままだった。遅延 50 ms ではボールが約 4 倍速で動き、「重い」のに「速く」見えた。
3. FIXED_DT スライダーが 0.5 ms 刻みで、既定の 16.7 が 16.5 に丸められていた。遅延 0 でも可変と固定の結果がずれていた（旧 0.330 / 0.323 の差はこれ）。

**変更**（`js/game-loop.js`、`js/maps/game-loop-config.js`、`algorithms/game-loop.html`）

1. 重力を 8 にした。床まで約 0.45 秒、止まるまで約 2.2 秒で、1× でも目で追える。
2. 人工遅延は描画の間隔そのものを伸ばす。重いフレームは「カクカクになるが、進む速さは同じ」に見える。再生速度もこの間隔に掛ける。計算に使う経過時間は決まった値（1000/60 ms ＋ 遅延）なので、同じ操作なら同じ結果になる。
3. 横軸を時間（3 秒分）にした。更新 1 回ごとの位置を小さい点、描画した位置を輪で残し、正解（同じ物理を 1 ms 刻みで計算）を点線で重ねる。3 秒分で自動で止まる。
4. 「遅延のかけ方: ときどき重い（5 フレームに 1 回）」を追加（URL `spike=1`）。正解の軌道の表示を切り替えられる（URL `ref`）。
5. キャンバスの左上に「このフレームの実経過・更新回数」を出す。
6. FIXED_DT は 0.1 ms 刻み。16.7 のように整数 Hz の周期に近い値は、その周期（1000/60）として扱う。

**実測**（ローカルのブラウザ、1× で 3 秒分）

| 条件 | 可変 最高点 / 停止 | 固定 最高点 / 停止 | 固定の更新/フレーム |
|---|---|---|---|
| 遅延 0 | 0.399 / 2233 ms | 0.399 / 2233 ms | 1.00 |
| 遅延 50 | 0.363 / 2067 ms | 0.399 / 2233 ms | 4.00 |
| 遅延 80・ときどき重い | 0.413 / 1797 ms | 0.399 / 2233 ms | 1.95 |
| 固定・遅延 80・MAX_STEPS 2 | — | 0.399 / 2233 ms（3 秒分に約 9 秒） | 2.00（毎フレーム打ち切り） |

正解（1 ms 刻み）は最高点 0.432、停止 2561 ms。

解説: ゲームの処理はイベントを出すだけで、音は購読側が決める。課題では Hit だけ 880 Hz になり、Jump は 440 Hz のままだった。

### 段5 状態と乱数（2 問）

**Q1.** 同じ Attack イベントでも、Idle のときと Dead のときで結果が違うのはなぜか。

- A. 次の状態は（今の状態, イベント）の組で決まるから **← 正解**
- B. イベントが届く順番がランダムだから
- C. Dead は Attack を受けると必ず Idle に戻る決まりだから
- D. 遷移表は見た目の説明で、実際の動きとは関係ないから

解説: 状態遷移は表の1行（今の状態, イベント）→ 次の状態で決まる。表に無い組み合わせは無視される。

**Q2.** 乱数とシードについて、課題で確かめられたことはどれか。

- A. 同じシードでも、生成するたびに系列は変わる
- B. 法 m を小さくすると、偏りのない良い乱数になる
- C. 同じシードなら同じ系列になり、法 m = 16 の LCG は 16 個以内で同じ並びを繰り返した **← 正解**
- D. XorShift にシード 0 を与えると、0 が並び続ける

解説: 状態は高々 m 通りなので周期は m を超えない。XorShift のシード 0 は全ゼロの固定点になるため、実装では別の値にずらしている（並ぶ乱数は 0 ではない）。

### 段6 考えるAI（3 問）

**Q1.** Min-Max で根の値が決まる仕組みはどれか。

- A. すべての葉の値の平均を取る
- B. 一番大きい葉を持つ手を選ぶ
- C. 自分の手番では子の最大、相手の手番では子の最小を取り、葉から根へ値を吸い上げる **← 正解**
- D. 左から順に読んで、最初に見つけた手を選ぶ

解説: 相手は自分に不利な手を選ぶと考える。課題では手 R の下に大きい葉があっても、相手が小さい方を選ぶので根は 7 になった。

**Q2.** 三目並べを空盤から、α-β 法を ON にして完全に読むとどうなったか。

- A. 根は引き分けのまま、訪問した局面が 549,945 から 30,709 に減った **← 正解**
- B. 訪問は減ったが、根の値が先手の勝ちに変わった
- C. 訪問した局面はちょうど半分になった
- D. 訪問した局面は変わらず、計算だけが速くなった

解説: α-β は答えに影響しない枝を読まないだけで、答えは Min-Max と同じ。空盤では根は引き分けのまま、訪問が 549,945 から 30,709 に減った。

**Q3.** 深さ制限で読み切れない局面を、0 と評価して打ち切るとどうなるか。

- A. 0 も評価関数の一種なので、全部読んだときと同じ手を選べる
- B. どの手も同じ値になって手を選べない。見積もりには評価関数が要る **← 正解**
- C. 根の値は必ず全部読んだときと同じになる
- D. 打ち切った枝は、選ばれないことが確定する

解説: 深さ 2 で 0 と評価すると根は 0、3手とも同点になった。配下の葉の平均で見積もると根 5.5 で、全部読んだときと同じ手 R を選べた。
