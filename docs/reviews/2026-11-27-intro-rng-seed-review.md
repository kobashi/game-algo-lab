## INTRO-RNG-01（P1） 提出 URL を開き直すとシードや周期が変わる

- **対象**　[既定値の取得と URL からの復元](../../js/rng-seed.js#L704)、[アルゴリズム切替時のプリセット適用](../../js/rng-seed.js#L641)、[既定値の省略](../../js/platform/url-params.js#L310)
- **再現**　入門デモで LCG を選び、シードを42に手入力して「生成」する。提出票の「今の設定を入れる」で保存して URL を開くと、シードが1になり、ダイスの並びが変わる。別の例では「質が悪い a が悪い（m=256）」を選び、「極小周期 m=16」のプリセットと同じ乗数・加数を手入力し、法を128にする。生成時の周期は128。保存した URL を開くと、乗数・加数が選択中のプリセットの値に戻って周期が1になる。
- **原因**　共有 URL は、ページ初期化時の値と一致する項目を省く。一方、URL を開くと「アルゴリズム」「プリセット」の復元でシードや係数が書き換わる。省いた項目はその時点の値のまま残る。このため、教員が同じ URL で観察結果を再現できない。
- **修正案**　保存時に、アルゴリズム・プリセットを適用した後も復元に必要な値を含める。LCG ではシード・サンプル数・乗数・加数・法を明示して共有する方法がある。既存のプリセット付き URL と、係数を明示する URL も引き続き解釈する。
- **修正後の確認**　法4種類の A/B を「今の設定を入れる」で保存し、新規タブで係数・シード・サンプル数・周期・ダイス列が一致することを確認する。プリセットと異なる値を設定し、その値がページの初期値と同じケースも含める。

## INTRO-RNG-02（P1） m=31 のプリセットで説明と実測が食い違う

- **対象**　[m=31 のプリセット](../../js/maps/rng-seed-config.js#L59)
- **再現**　LCG の「小フル周期 m=31」を選ぶ。説明は `c=0` でない場合の周期31を示すが、表示された式の `c` は0、シード1での実測は30。
- **原因**　プリセットの表示名・説明が、設定の `a=3, c=0, m=31` と一致していない。
- **修正案**　既存の設定を使うなら、シード1で測る周期30の乗算合同法の例として説明する。周期31の例として残すなら、設定を実測31になる組へ合わせる。
- **修正後の確認**　プリセット切替とプリセット指定 URL の両方で、表示名・式・シード・実測周期が一致することを確認する。

## INTRO-RNG-03（P2） 周期を数える練習から、条件を探す課題への橋渡しがない

- **対象**　[詳説の手計算と問い](../../courses/guide-rng-seed.html#L132)、[C# の周期測定](../../courses/cs-rng-seed.html#L257)、[観察演習](../../js/courses/intro-exercises.js#L198)、[提出課題](../../js/courses/intro-assignments.js#L265)、[デモの Hull–Dobell の表示](../../js/rng-seed.js#L253)
- **再現と原因**　詳説では `m=5` で既知の設定を手計算し、続く問いでは `a,c,m` をいろいろ変えるよう促す。観察演習は同じシードの再現、極小の `m`、XorShift のシード0を扱う。デモに最大周期の条件の一部は表示されるが、中学生が割り切れる条件や候補の選び方を学ぶ流れにはなっていない。提出課題も、比較条件や試行の記録は求めていないため、例を転用して周期だけ確認しても提出物を作れる。
- **修正案**　例えば8マスの輪で `a=1` に固定し、奇数歩と偶数歩を図で追う。最初の数回を予想してからデモで確認する。提出実験では割り当てられた `m`・シード・サンプル数を揃え、`a,c` の片方だけを動かして、予想と実測の根拠を記録させる。今回の `m` はすべて2の累乗なので、その場合の判定は発展に置ける。[Hull・Dobell の原論文](https://dspace.library.uvic.ca/items/d6e64ce3-16eb-4f26-b544-0cb22ef0647b)
- **修正後の確認**　詳説の手順から候補を選び、試行前に短くなる方を予想してから、周期の差と理由を説明できる。採点例には、誤った `m` や同一設定の A/B を区別する確認項目を入れる。現行の提出票は同じトピックに見える URL の形式を確認する。実際に、割り当てと異なる `m` を含む同一 URL を A/B に入れても警告は出なかった。[URL の形式チェック](../../js/platform/submission.js#L44)

## INTRO-RNG-04（P2） 周期と、繰り返しに入るまでの長さが混同される

- **対象**　[詳説の周期の定義](../../courses/guide-rng-seed.html#L180)、[周期計測の実装](../../js/rng-seed.js#L200)、[C# 解説](../../courses/cs-rng-seed.html#L257)
- **再現と原因**　詳説で「繰り返しが始まるまでの長さ」を周期と説明している。デモで `a=2,c=0,m=256`・シード7のプリセットを選ぶと、最初は値が変わり、やがて0に留まって実測は周期1となる。デモと C# は、同じ状態が現れた2時点の差を周期として数えている。
- **修正案**　周期を「繰り返す部分1周の長さ」と説明する。最初の数が輪に入っていない例も図に足し、仕様と実装コメントの表現を揃える。
- **修正後の確認**　最初から輪の中にいる例と、途中から0を繰り返す例の両方で、図から数えた周期とデモの表示が一致する。

## INTRO-RNG-05（P2） ヒストグラムから周期や乱数の質まで判断できるように読める

- **対象**　[詳説のヒストグラム](../../courses/guide-rng-seed.html#L224)、[提出物の観察項目](../../js/courses/intro-assignments.js#L270)、[生成数の上限](../../js/maps/rng-seed-config.js#L19)
- **再現と原因**　詳説は棒が揃う図を「良い例」とする。ヒストグラムが表すのは出現回数で、値の順番が変わっても同じ形になる。デモは生成数が既定48、最大128で、法256・512の最大周期はヒストグラムのサンプルに1周分入らない。周期パネルは別途状態をたどるため、生成数を増やさなくても測れる。
- **修正案**　周期は周期パネルで、偏りの手掛かりは同じサンプル数のヒストグラムで確認する。小さい `m` で全状態を規則的に順番に通る列も示し、周期・出現回数・順番の3点を問い分ける。
- **修正後の確認**　並びだけを変えた同じ値の集合を見て、棒は同じでも順番が異なることを説明できる。法256の比較で、観察と考察がサンプル数と周期を混同しない。

## INTRO-RNG-06（P2） ゲームへの応用が提出課題の体験につながっていない

- **対象**　[詳説のリプレイ説明](../../courses/guide-rng-seed.html#L125)、[観察演習の発展](../../js/courses/intro-exercises.js#L198)、[デモのダイス表示](../../js/rng-seed.js#L581)
- **再現と原因**　詳説はゲームの敵出現・アイテム配置・カードの並びを紹介する。演習は数列の再生成、提出課題は LCG の最大周期の探索で終わる。詳説の「同じシードを保存しておけば、ゲームの展開をもう一度そのまま作り直せます」という説明は、同じ初期状態・処理・入力順で乱数を同じように使う条件を省いている。
- **修正案**　入門の主課題に、既存の6面ダイスを「出現する敵の種類」などに対応させ、同じシードと設定で先頭数回を再現し、シードを変えた場合と比べる体験を入れる。発展で LCG の周期を扱い、短い周期なら敵の出現パターンが繰り返しやすいことを観察する。対話を含むリプレイでは同じ初期状態・入力列も要ることを説明する。[リプレイ教材](../../algorithms/replay-determinism.html#L15)
- **修正後の確認**　学習者がダイスの数値からゲーム内の結果を読み取り、同じ場面を再現するために揃える情報を説明できる。周期の実験はその後に行う。
