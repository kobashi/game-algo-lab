1. このコードがすること

このファイルには、次の 4 つがあります。

  • ActionState: 1 つのボタン（キー）の状態を持つクラス。Held・Down・Up・HoldTime・LongPressFired を持ちます。
  • InputBasicsExample.Poll: 毎フレーム呼ぶ関数。前フレームの Held と、今フレームの生の isDownNow（実際にキーが押されているか）から、Down・Up・HoldTime を更新します。
  • InputBasicsExample.ConsumeLongPress: HoldTime が閾値を超えたフレームで、1 回だけ true を返します。
  • InputBasicsExample.ApplyFire: デモの Fire（Z）。押しているあいだは回数を毎フレーム 1 足し、離したフレーム（Up）で 0 に戻します。

キーボードやマウスを実際に読む部分（isDownNow を作るところ）は入っていません。held・down・up・長押しの考え方は くわしい解説を先に読んでください。

2. 新しく出てくる C# の文法

2.1 bool 型 — C の「0 でなければ真」とは違う

public bool Held;

C では、真偽を int の 0（偽）・0 以外（真）で表します（C99 の _Bool・stdbool.h の bool も中身は整数で、if には int をそのまま書けます）。 C# には、真偽だけを表す bool 型があり、値は true か false のどちらかだけです。

C

int held;
if (held) { ... }   // 0 以外なら真

C#

bool held;
if (held) { ... }   // true でなければコンパイルエラー

C# では int を bool の代わりに使えません。if (1) のように書くと、コンパイルエラーになります。 実際に int flag = 1; if (flag) { } と書いてコンパイルすると、次のエラーになります。 

error CS0029: Cannot implicitly convert type 'int' to 'bool'

int から bool への暗黙の変換もありません。真偽は、必ず比較や論理式（==・<・&& など）から作ります。

2.2 比較・論理式の結果を bool 変数に代入する

bool prev = state.Held;
state.Held = isDownNow;
state.Down = state.Held && !prev;
state.Up = !state.Held && prev;

&&（かつ）や !（否定）は C と同じ書き方ですが、C# では結果がそのまま bool の値になるので、 if を使わずに bool の変数へ直接代入できます。state.Held && !prev は「今 held で、かつ前は held でなかった」という 1 つの真偽値です。

2.3 if・else の { } 省略

if (state.Held)
    state.HoldTime += dtSeconds;
else
{
    state.HoldTime = 0;
    state.LongPressFired = false;
}

文が 1 つだけのときは、C と同じく { } を省略できます。if 側は 1 文なので省略、else 側は 2 文なので { } が要ります。 C と同じ注意点として、あとから if 側に文を 1 つ足すと、その文は if の中に入らず、いつも実行されてしまいます。

2.4 使っていない using

using System.Collections.Generic;

このファイルには List や Dictionary（第 9 回で説明します）は出てきません。使っていない using を書いてもエラーにはならず、 コンパイルできます。C の使っていない #include と同じで、害はありませんが、あとで使う予定がある場合や、書き直す前の名残りとして残っていることがあります。

2.5 名前の付け方の慣習

C# にはコンパイラが強制するルールではありませんが、広く使われている名前の付け方があります。 public なクラス名・メソッド名・フィールド名は、単語の頭を大文字にするパスカルケース（ActionState・HoldTime・Poll）。 引数やメソッドの中のローカル変数は、最初の単語だけ小文字にするキャメルケース（isDownNow・dtSeconds・prev）です。 

public static void Poll(
    ActionState state,
    bool isDownNow,
    double dtSeconds,
    double longPressThresholdSeconds)

Poll（パスカルケース、public なメソッド）に対して、isDownNow・dtSeconds（キャメルケース、引数）という書き分けが見えます。

これまでに出たもの: using（第 1 回）、public static class（第 1 回）、/// のコメント（第 1 回）。
C と同じもの: &&・!、+=、比較演算子、コメントの //。

3. 計算式とアルゴリズムのポイント

3.1 エッジ検出（前フレームとの比較）

bool prev = state.Held;
state.Held = isDownNow;
state.Down = state.Held && !prev;
state.Up = !state.Held && prev;

Down・Up の求め方は、くわしい解説の表と同じです。 大事なのは順番です。まず prev に今までの Held を保存してから、Held を新しい値に書き換えます。 先に state.Held = isDownNow; をしてしまうと、prev に入るのが「前フレーム」ではなく「今フレーム」の値になり、 Down・Up が正しく求まりません。

3.2 HoldTime の増加とリセット

if (state.Held)
    state.HoldTime += dtSeconds;
else
{
    state.HoldTime = 0;
    state.LongPressFired = false;
}

押しているあいだ（Held）は、HoldTime に毎フレーム dtSeconds を足し続けます。 離すと、HoldTime を 0 に戻し、LongPressFired（長押しをもう発火したか）も戻します。次に押したときに、また 0 から数えられるようにするためです。

3.3 長押しは 1 回だけ発火

if (!state.Held || state.LongPressFired) return false;
if (state.HoldTime < longPressThresholdSeconds) return false;
state.LongPressFired = true;
return true;

ConsumeLongPress は、次の 2 つのどちらかなら false を返して終わります。押していない、またはもう発火した（1 行目）。まだ閾値に届いていない（2 行目）。 どちらでもなければ、LongPressFired を true にしてから true を返します。 次のフレームでは 1 行目の条件に当てはまるので、押し続けても 2 回目は発火しません。

3.4 Fire は held で増え、up で 0 に戻る

if (state.Held)
    fireCount += 1;
if (state.Up)
    fireCount = 0;

デモの Z（Fire）は、押しているあいだ毎フレーム回数を 1 足します。離したフレームでは Held が false、Up が true なので、足さずに 0 へ戻します。 Jump の回数は押した瞬間に増えたあと残りますが、Fire の回数はキーを離すと消えます。

4. 呼び出してみる（Main と出力）

次のコードは、60 FPS（dt = 1/60）で、キーを 25 フレームぶん押し続けてから離す状況を作ります。長押しの閾値は 0.4 秒です。 Down・Up・長押しが起きたフレームだけを表示します。 

using System;

public static class Program
{
    public static void Main()
    {
        ActionState state = new ActionState();
        double dt = 1.0 / 60;
        double threshold = 0.4;

        for (int frame = 1; frame <= 30; frame++)
        {
            bool isDownNow = frame <= 25;
            InputBasicsExample.Poll(state, isDownNow, dt, threshold);
            bool longPress = InputBasicsExample.ConsumeLongPress(state, threshold);

            if (state.Down || state.Up || longPress)
            {
                Console.WriteLine("frame " + frame
                    + ": held=" + state.Held
                    + " down=" + state.Down
                    + " up=" + state.Up
                    + " holdTime=" + Math.Round(state.HoldTime, 3)
                    + " longPress=" + longPress);
            }
        }
    }
}

実行結果:

frame 1: held=True down=True up=False holdTime=0.017 longPress=False
frame 25: held=True down=False up=False holdTime=0.417 longPress=True
frame 26: held=False down=False up=True holdTime=0 longPress=False
  • フレーム 1 で down=True。押し始めの 1 フレームだけです。
  • bool を文字列につなげると、"True"・"False"（先頭が大文字）になります。
  • 長押しは、HoldTime が 0.4 秒を超えたフレーム 25 で 1 回だけ発火します。dt を 24 回足した値は、計算上ちょうど 0.4 のはずですが、 小数の足し算をくり返すと少しの誤差が出て、24 フレーム目はわずかに 0.4 に届きません。そのため発火は 1 フレームあとの 25 になります。
  • フレーム 26 で isDownNow が false になり、up=True。holdTime は 0 に戻っています。

5. まとめと、やってみよう

この回で出てきた C# の文法です。後の回では、ここへのリンクだけを置きます。

文法ひとことでC では
bool真偽だけを表す型。int は使えない（型がなく int で代用）
比較・論理式を bool に代入a && !b を直接代入できる同じ書き方（型は int）
if・else の { } 省略1 文なら省略できるC と同じ
使っていない using書いてもエラーにならない使っていない #include と同じ
名前の付け方の慣習public はパスカルケース、引数・ローカルはキャメルケース—

やってみよう

  1. 4 節の threshold を 0.25 に変えて、長押しが発火するフレームがどう変わるか予想してから確かめる。
  2. isDownNow を 10 フレーム目だけ false にして（押している途中で一瞬離す）、HoldTime と LongPressFired がどうなるかを確かめる。
  3. 4 節のループで ApplyFire も呼び、離したフレームで回数が 0 になることを確かめる。

確かめよう

問 1. Poll の中で、state.Held = isDownNow; より先に bool prev = state.Held; をするのはなぜ？

先に Held を書き換えてしまうと、prev に「前フレームの値」ではなく「今フレームの値」が入ってしまい、Down・Up を正しく求められないからです。

問 2. int flag = 1; if (flag) { } と書くと、C# ではどうなる？

コンパイルエラーになります（int から bool への暗黙の変換がないため）。C ならそのまま真として動きます。

問 3. キーを押し続けているのに、ConsumeLongPress が 2 回目以降 false を返すのはなぜ？

LongPressFired が true になっているからです。最初の行の state.LongPressFired のチェックで、すぐ false が返ります。
