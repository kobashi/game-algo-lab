1. このコードがすること

UiLayout.TopLeft は、Anchor（親のどこを基準にするか）・Pivot（自分のどの点を合わせるか）・Offset（px のずれ）と、 親の大きさ・自分の大きさを受け取り、UI 要素の左上の座標を計算して返す 1 つの関数です。

画面に実際に描く処理は入っていません。位置を計算するだけの、純粋な関数です。

2. 新しく出てくる C# の文法

2.1 引数が多いときの改行

public static (float x, float y) TopLeft(
    float parentW, float parentH,
    float anchorX, float anchorY,
    float pivotX, float pivotY,
    float offsetX, float offsetY,
    float w, float h)

TopLeft は引数が 10 個もあります。C と同じく、C# も ( と ) の間であれば、 好きなところで改行してかまいません。ここでは、意味のまとまりごと（親の大きさ・Anchor・Pivot・Offset・自分の大きさ）に 2 個ずつ改行して並べ、読みやすくしています。動きには関係なく、見た目だけの工夫です。

2.2 名前付き引数

呼び出すときに、引数名: 値 の形で書くと、順番を気にせず渡せます。これを名前付き引数といいます。 

UiLayout.TopLeft(
    parentW: 640, parentH: 480,
    anchorX: 0f, anchorY: 0.5f,
    pivotX: 0f, pivotY: 0.5f,
    offsetX: 16f, offsetY: 0f,
    w: 100f, h: 30f);

TopLeft は float の引数ばかり 10 個並んでいるので、順番だけを頼りに呼び出すと、 anchorX と pivotX を取り違えるといったミスが起きやすくなります。名前を書けば、 どの値がどの引数なのかがその場で分かります。C には、この書き方はありません（引数は並べた順番だけで決まります）。

これまでに出たもの: 名前付きタプルの戻り値（第 1 回）、static class・public static（第 1 回）、 float と f サフィックス（第 4 回）。 C と同じもの: 括弧の中の自由な改行、*・+・-。

3. 計算式とアルゴリズムのポイント

3.1 Anchor の位置（px に変換）

float ax = anchorX * parentW;
float ay = anchorY * parentH;

anchorX・anchorY は 0〜1 の割合（正規化座標）です。 親の大きさ（parentW・parentH）を掛けると、px での Anchor の位置になります。

3.2 左上の座標を求める式

return (ax + offsetX - pivotX * w, ay + offsetY - pivotY * h);

くわしい解説の式 「箱の左上 ＝ Anchor の位置 ＋ Offset − Pivot × 箱の大きさ」を、 x・y それぞれについてそのままコードにしたものです。pivotX * w は、自分の大きさのうち Pivot が示す位置までの距離です。

3.3 落とし穴: 名前付き引数でも、省略できる引数は増えない

名前付き引数は「順番を変えられる」だけで、引数の数そのものを減らせるわけではありません。h（自分の高さ）を書き忘れて呼び出すと、 名前付きで書いていても、次のようにコンパイルエラーになります。 

UiLayout.TopLeft(
    parentW: 640, parentH: 480,
    anchorX: 0f, anchorY: 0.5f,
    pivotX: 0f, pivotY: 0.5f,
    offsetX: 16f, offsetY: 0f,
    w: 100f);
// エラー: CS7036 There is no argument given that corresponds to
// the required parameter 'h' of 'UiLayout.TopLeft(...)'

TopLeft の引数には既定値（省略したときの値）が 1 つも無いので、10 個すべてを渡す必要があります。

4. 呼び出してみる（Main と出力）

サンプルには実行の入口がないので、次のようなファイルを足して動かします。親（画面）を 640 × 480、 Anchor を左のふちの真ん中 (0, 0.5)、Pivot も自分の左のふちの真ん中 (0, 0.5)、Offset を (16, 0)、 自分の大きさを 100 × 30 にした例です。 

using System;

public static class Program
{
    public static void Main()
    {
        (float x, float y) pos = UiLayout.TopLeft(
            parentW: 640, parentH: 480,
            anchorX: 0f, anchorY: 0.5f,
            pivotX: 0f, pivotY: 0.5f,
            offsetX: 16f, offsetY: 0f,
            w: 100f, h: 30f);
        Console.WriteLine("left=" + pos.x + ", top=" + pos.y);
    }
}

実行結果:

left=16, top=225
  • Anchor は (0, 0.5) なので、px では (0, 240)（画面の左のふちの真ん中）です。
  • Pivot も (0, 0.5) なので、pivotX * w = 0、pivotY * h = 15（自分の高さの半分）です。
  • 左上の x は 0 + 16 - 0 = 16、y は 240 + 0 - 15 = 225 になります。

名前付き引数の順番を入れ替えて（anchorX を先に、parentW を後に、のように）同じ値で呼び出しても、 結果は同じ left=16, top=225 になることを確認しています。

5. まとめと、やってみよう

この回で出てきた C# の文法です。後の回では、ここへのリンクだけを置きます。

文法ひとことでC では
引数が多いときの改行括弧の中は自由に改行できる。意味のまとまりで分けると読みやすい同じ（自由）
名前付き引数名前: 値 で呼ぶ。順番を入れ替えられる無い（位置だけで決まる）

やってみよう

  1. 4 節の呼び出し例の offsetX・offsetY を別の値に変えて、左上の座標がどう変わるか確かめる。
  2. 4 節の呼び出し例から w か h のどちらかを 1 つ抜いて呼び出し、3.3 節と同じエラーになることを確かめる。

確かめよう

問 1. 名前付き引数を使うと、何が読みやすくなる？

float ばかりが並ぶ呼び出しで、どの値がどの引数なのかが、名前を見るだけで分かるようになります。

問 2. 名前付き引数で呼び出すとき、必須の引数を 1 つ書き忘れるとどうなる？

コンパイルエラーになります。名前付きでも、既定値の無い引数は省略できません。

問 3. Anchor (0, 0.5)・Pivot (0, 0.5)・Offset (16, 0)、親 640×480、自分 100×30 のとき、左上の x 座標は？

16 です。Anchor の x（0×640＝0）に Offset の x（16）を足し、Pivot×幅（0×100＝0）を引くと 16 になります。
