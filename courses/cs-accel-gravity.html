1. このコードがすること

Body2D は 1 つの構造体で、次の 2 つのメソッドを持ちます。

  • Integrate(dt): 重力で縦の速さ Vy を変え、その速さで位置 X・Y を動かします。自分のフィールドを直接書き換えます。
  • BounceFloor(floorY, restitution): 床（floorY）を超えていたら、位置を床の上に戻し、縦の速さの向きを反転して弱めます。

2. 新しく出てくる C# の文法

2.1 float と double

public float X, Y, Vx, Vy;
public float Gravity; // a.y

C と同じく、C# にも小数を表す型が 2 つあります。float（単精度。約 7 桁の精度）と double（倍精度。約 15 桁の精度）です。 これまでのサンプル（第 1 回・第 3 回）は double を使っていましたが、このサンプルは float です。

C# の小数リテラル（3.14 のような数の書き方）は、既定で double として扱われます。float の変数に代入するには、数の後ろに f を付けます。 実際に f を付けずに書いてコンパイルすると、次のエラーになります。 

float f = 3.14;
// error CS0664: Literal of type double cannot be implicitly
// converted to type 'float'; use an 'F' suffix to create a literal of this type

また、double の変数を float の変数へ代入することも、暗黙にはできません（精度が落ちるため）。 

double d = 3.14;
float f = d;
// error CS0266: Cannot implicitly convert type 'double' to 'float'.
// An explicit conversion exists (are you missing a cast?)

逆に float を double の変数へ入れるのは、精度が広がる方向なので暗黙にできます。狭くなる変換だけ、キャスト（(float)d）が必要です。

2.2 struct のメソッドが自分のフィールドを書き換える

public void Integrate(float dt)
{
    Vy += Gravity * dt;
    X += Vx * dt;
    Y += Vy * dt;
}

第 3 回の Vec2.Integrate は static で、新しい値を return していました。 こちらの Integrate は static が付いておらず、this（呼び出したボディ自身）の Vy・X・Y を直接書き換えます。 class のメソッドと同じ書き方ですが、Body2D は struct（値型）のままです。

2.3 コピーの落とし穴

struct は値型なので、変数へ取り出したり配列の要素をコピーしたりすると、そのコピーに対して Integrate を呼んでも、元の値は変わりません。 実際に試すと、次のようになります。 

Body2D[] bodies = new Body2D[1];
bodies[0] = new Body2D();
bodies[0].Vy = 100f;
bodies[0].Gravity = 600f;

bodies[0].Integrate(1f / 60f); // 配列の要素に直接呼ぶ → 配列の中身が変わる
Console.WriteLine("array element: y=" + bodies[0].Y);

Body2D copy = bodies[0]; // ここで値がコピーされる
copy.Integrate(1f / 60f); // copy だけが変わる
Console.WriteLine("local copy:    y=" + copy.Y);
Console.WriteLine("array element (unchanged): y=" + bodies[0].Y);
array element: y=1.8333334
local copy:    y=3.8333335
array element (unchanged): y=1.8333334

bodies[0].Integrate(...) は配列の要素そのものを書き換えるので、Y が変わります。 いっぽう、いったん Body2D copy = bodies[0]; で別の変数に取り出すと、それはコピーです。copy.Integrate(...) は copy だけを変え、bodies[0] はそのままです。 関数の引数に渡すときも同じことが起きます。「配列やフィールドから読み出した struct を、いったん別の変数に入れてから使う」ときは注意してください。

2.4 BounceFloor の -Vy（Math.Abs を使わない）

public void BounceFloor(float floorY, float restitution)
{
    if (Y > floorY)
    {
        Y = floorY;
        Vy = -Vy * restitution;
    }
}

第 1 回の BallWorld.Update は、床に着いたとき -Math.Abs(V) * Restitution と書いていました。 Abs で向きを消してから - を付けるので、V がどんな符号でも必ず上向きになります。

こちらの BounceFloor は、Abs を使わず -Vy * restitution とだけ書いています。 Integrate が先に重力で Vy を増やしてから位置を進めるので、床を超えた瞬間はふつう Vy が下向き（正）になっており、-Vy で上向きに変わります。 ただし、これは「床にぶつかる瞬間は必ず下向きに動いている」という前提に頼った書き方です。Math.Abs を使う書き方のほうが、その前提が崩れても安全です。

これまでに出たもの: public（第 1 回）、struct（第 3 回）。
C と同じもの: +=、-（単項）、比較演算子 >。

3. 計算式とアルゴリズムのポイント

3.1 速さ ← 速さ ＋ g・dt、位置 ← 位置 ＋ 速さ・dt

Vy += Gravity * dt;
X += Vx * dt;
Y += Vy * dt;

くわしい解説の 1 節の式そのままです。Vx は重力の影響を受けないので変わらず、X は毎フレーム同じだけ進みます。 Vy だけが重力で増えていくので、Y の進み方はだんだん大きくなります（2 節の表・4 節の放物線）。

3.2 床での跳ね返り

if (Y > floorY)
{
    Y = floorY;
    Vy = -Vy * restitution;
}

Y = floorY; で床にめり込んだ分を戻し（5 節）、Vy = -Vy * restitution; で向きを反対にして弱めます。 跳ね上がる高さが反発係数の 2 乗に比例することは、くわしい解説の 6 節で説明しています。

3.3 なぜコピーだと変わらないのか

2.3 節の結果は、struct が値型であることの直接の結果です。Body2D copy = bodies[0]; の行で、bodies[0] の X・Y・Vx・Vy・Gravity の値が、 すべて copy という別の場所にコピーされます。そのあと copy.Integrate(...) が書き換えるのは、この別の場所のフィールドだけです。 bodies[0] 自身のフィールドは、どこからも触られていないので変わりません。

4. 呼び出してみる（Main と出力）

重力 600、反発係数 0.6、床 floorY = 100、dt = 1/60 秒で、40 フレーム落として、5 フレームおきに Y・Vy を表示します。 

using System;

public static class Program
{
    public static void Main()
    {
        Body2D body = new Body2D();
        body.Gravity = 600f;
        body.Y = 0f;
        float floorY = 100f;
        float restitution = 0.6f;
        float dt = 1f / 60f;

        for (int frame = 1; frame <= 40; frame++)
        {
            body.Integrate(dt);
            body.BounceFloor(floorY, restitution);

            if (frame % 5 == 0)
                Console.WriteLine("frame " + frame + ": y=" + Math.Round(body.Y, 2) + " vy=" + Math.Round(body.Vy, 2));
        }
    }
}

実行結果:

frame 5: y=2.5 vy=50
frame 10: y=9.17 vy=100
frame 15: y=20 vy=150
frame 20: y=35 vy=200
frame 25: y=54.17 vy=250
frame 30: y=77.5 vy=300
frame 35: y=100 vy=-210
frame 40: y=85 vy=-160

フレーム 5〜30 では y と vy がだんだん大きくなり、落ちる速さが増えています。フレーム 30〜35 のあいだで床（y=100）に着き、 フレーム 35 では vy がマイナス（上向き）に変わって跳ね返っていることが分かります。body.Y や body.Vx は初期値 0 のままにしています。

5. まとめと、やってみよう

この回で出てきた C# の文法です。後の回では、ここへのリンクだけを置きます。

文法ひとことでC では
float・double精度が違う 2 つの小数型。float は f サフィックスが要るC と同じ 2 つの型がある
double→float の暗黙変換できない（キャストが要る）。逆はできる暗黙に変換される（精度が落ちる）
可変 struct値型のままメソッドが自分のフィールドを書き換えられる—（構造体を受け取る関数がポインタ経由で書き換える）
struct のコピーの落とし穴別変数・配列から取り出すとコピー。書き換えても元は不変構造体の代入と同じ

やってみよう

  1. 4 節の restitution を 0.8 に変えて、跳ね返ったあとの vy の絶対値が、跳ね返る前よりどれだけ小さくなるかを確かめる。
  2. 2.3 節のコードで、copy.Integrate(...) の代わりに bodies[0].Integrate(...) をもう一度呼んだらどうなるかを予想してから確かめる。

確かめよう

問 1. float f = 3.14; と書くと、C# ではどうなる？

コンパイルエラーになります（CS0664）。3.14 は既定で double のリテラルなので、3.14f と書く必要があります。

問 2. Body2D copy = bodies[0]; のあと copy.Integrate(dt); を呼んでも bodies[0] が変わらないのはなぜ？

struct は値型なので、copy には bodies[0] の値のコピーが入っています。copy を書き換えても、bodies[0] という別の場所には影響しません。

問 3. BounceFloor が -Vy * restitution でなく -Math.Abs(Vy) * restitution だったら、何が変わる？

Vy がすでに上向き（マイナス）のときに BounceFloor が呼ばれても、必ず上向きの結果になります。-Vy だけだと、その場合は下向きになってしまいます。
