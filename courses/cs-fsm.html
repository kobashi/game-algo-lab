1. このコードがすること

このファイルには、StateMachine クラスが 1 つあります。

  • コンストラクタで、初期状態と遷移表（Dictionary<string, string>）を受け取ります。
  • Current: 今の状態。外からは読めますが、書き換えられません。
  • History: これまで通ってきた状態の列。読み取り専用として公開します。
  • TryHandle(eventId): イベントを 1 つ処理します。遷移表に定義があれば状態を進めて true、無ければ無視して false を返します。

状態・イベント・遷移そのものの考え方はくわしい解説にあります。ここでは、そのルールがコードでどう書かれているかに集中します。

2. 新しく出てくる C# の文法

2.1 { get; private set; }: 外からは読むだけ

public string Current { get; private set; }

自動実装プロパティ { get; set; } は第 6 回で出てきました。 ここでは set の前に private が付いています。get（読み出し）はクラスの外からもできますが、 set（書き込み）は StateMachine クラスの中からしかできません。

C には、こういう「読むのは自由だが書けるのは中だけ」という仕組みがありません。ふつうは、書き換える関数だけを公開して、 フィールドを直接触らせないようにする、といった工夫で似たことをします。

2.2 式形式プロパティと IReadOnlyList<T>

public IReadOnlyList<string> History => _history;

=> で 1 行の式をそのまま返す書き方は（第 3 回）に出てきました。ここでは、プロパティ全体を get だけの式にして、内部のフィールド _history（List<string>、第 9 回）をそのまま返しています。

型が List<string> ではなく IReadOnlyList<string> になっている点に注目してください。 ジェネリクスの書き方自体は第 9 回と同じですが、IReadOnlyList<T> には Add や Remove がありません。 foreach で回したり、Count や添字で読んだりはできますが、書き換える手段が型として無いのです。 呼び出す側が誤って履歴を書き換えてしまう心配がありません。

2.3 new() によるフィールドの初期化（復習）

private readonly List<string> _history = new();

新しい文法ではありません。第 3 回の new(...)（型を省略した new）と、第 9 回の readonly を、 フィールドの宣言の場所で組み合わせただけです。「_history は別のリストに差し替えられないリストで、宣言と同時に空のリストで始める」という意味になります。

2.4 TryGetValue と out var

if (!_transitions.TryGetValue(key, out var next))
    return false;

Dictionary<TKey, TValue> は第 9 回で出てきましたが、TryGetValue は新しいメソッドです。 「キーがあったかどうか」を bool の戻り値で返しつつ、「あったときの値」を out 引数に書き込みます。

C（見つかったかを戻り値、値をポインタで受け取る）

const char *next;
if (!dict_try_get(transitions, key, &next)) {
    return false;
}

C#（out でその場に変数を作って受け取る）

if (!_transitions.TryGetValue(key, out var next))
    return false;

第 1 回の ref は「すでにある変数を書き換える」ものでしたが、out は「呼ばれた側が必ず値を書き込む」約束の引数です。 呼び出し前に next を用意しておく必要はありません。out var next のように、呼び出しの中でその場に変数を宣言できます。

これまでに出たもの: readonly・Dictionary<TKey, TValue>・var・foreach（第 9 回）、 自動実装プロパティ { get; set; }（第 6 回）、コンストラクタ・式形式メンバー =>（第 3 回）、 new(...) の省略形（第 3 回・第 9 回）。

C と同じもの: if・!・return。

3. 計算式とアルゴリズムのポイント

遷移のルールそのもの（状態図・遷移表の読み方）はくわしい解説の 3 節にあります。 ここでは、そのルールがコードでどう表されているかだけを見ます。 

var key = Current + "|" + eventId;
if (!_transitions.TryGetValue(key, out var next))
    return false;

Current = next;
_history.Add(next);
return true;
  • 「今の状態」と「イベント」を "|" でつないだ 1 本の文字列を作り、それを遷移表のキーにします。 Current が "Idle"、eventId が "Move" なら、キーは "Idle|Move" です。
  • そのキーで Dictionary を引きます。見つからなければ、そのイベントはその状態では定義されていない、つまり無視です（false を返し、状態はそのまま）。
  • 見つかれば、Current を次の状態に書き換え、_history に積んでから true を返します。
落とし穴: キーの照合は文字どおりの一致です。"|" の代わりに別の区切り文字を使ったり、 大文字・小文字や余分な空白が違ったりすると、TryGetValue は静かに「見つからない」を返します。 例外にもならず、ただイベントが無視された状態になるので、遷移表の作り方と eventId の綴りは正確に合わせる必要があります。

4. 呼び出してみる（Main と出力）

次のような遷移表（デモの js/maps/fsm-config.js の一部）を作って、いくつかイベントを送ってみます。 

using System;
using System.Collections.Generic;

public static class Program
{
    public static void Main()
    {
        var transitions = new Dictionary<string, string>();
        transitions["Idle|Move"] = "Walk";
        transitions["Idle|Jump"] = "Jump";
        transitions["Walk|Stop"] = "Idle";
        transitions["Walk|Jump"] = "Jump";
        transitions["Jump|Land"] = "Idle";

        var fsm = new StateMachine("Idle", transitions);

        Report(fsm, "Move");
        Report(fsm, "Jump");
        Report(fsm, "Land");
        Report(fsm, "Land");

        Console.Write("history:");
        foreach (var s in fsm.History)
        {
            Console.Write(" " + s);
        }
        Console.WriteLine();
    }

    private static void Report(StateMachine fsm, string eventId)
    {
        bool handled = fsm.TryHandle(eventId);
        Console.WriteLine(eventId + " -> " + fsm.Current + " (handled=" + handled + ")");
    }
}

実行結果:

Move -> Walk (handled=True)
Jump -> Jump (handled=True)
Land -> Idle (handled=True)
Land -> Idle (handled=False)
history: Idle Walk Jump Idle
  • Idle に Move が来て Walk へ、Walk に Jump が来て Jump へ、Jump に Land が来て Idle へと、遷移表どおりに進みます。
  • 最後の Land はもう一度送っています。Idle には Land の定義が無いので、handled=False になり、状態は Idle のまま変わりません。
  • History を foreach で読み出すと、初期状態から順に Idle Walk Jump Idle と積まれているのが分かります。無視された Land は履歴に足されません。

確かめよう

問 1. Current が { get; private set; } になっているのはなぜ？

クラスの外から fsm.Current = "Dead"; のように直接書き換えられないようにするためです。状態を変えるのは TryHandle の中だけにしたいからです。

問 2. TryGetValue が false を返したとき、out で受け取った next の中身をそのまま使っても大丈夫？

大丈夫ではありませんが、このコードでは false のときに return false; しているので、そもそも next を使いません。false のときの next は既定値（string なので null）です。

問 3. History の型が List<string> ではなく IReadOnlyList<string> なのはなぜ？

呼び出し側が Add や Remove で履歴を書き換えられないようにするためです。読むための操作だけを持つ型として公開しています。
