1. このコードがすること

このファイルには、次の 3 つがあります。

  • MmKind: 節点の種類（自分の番・相手の番・葉）を表す列挙型。
  • MmNode: ゲーム木の 1 つの節点。種類・スコア・子のリストを持つ。
  • Minimax: Evaluate（枝刈りなしの素の Min-Max）と EvaluateWithDepthLimit（深さ制限つき）の 2 つの静的メソッドを持つ。

木そのものは、このファイルの外（呼び出す側や、デモの js/maps/minimax-config.js）で組み立てます。 考え方はくわしい解説で図を使って説明しているので、ここではコードとの対応に絞って説明します。

2. 新しく出てくる C# の文法

2.1 enum: 種類をまとめた小さな仲間

public enum MmKind
{
    Max,  // 自分（最大化）
    Min,  // 相手（最小化）
    Leaf  // 終端評価
}

C にも enum はありますが、C の enum の中身（MAX や MIN など）は、そのまま外側の名前空間に出てきます。 C# の enum は違います。値は MmKind という型の中に閉じ込められていて、使うときは 必ず型名を付けて MmKind.Max のように書きます。

C で書くと

enum MmKind { MAX, MIN, LEAF };
...
if (kind == MAX) { ... }  // 型名なしで書ける

C# のサンプル（抜き出し）

if (n.Kind == MmKind.Max)

試しに型名を省いて if (k == Max) と書くとどうなるか確かめると、error CS0103: The name 'Max' does not exist in the current context というエラーになります。 Max だけでは、コンパイラは「何の Max か」を見つけられません。

2.2 int?: 値がないかもしれない int

public int? Score { get; } // Leaf のみ

MmNode は葉以外（MAX・MIN の節点）だとスコアを持ちません。C なら「スコアがない」ことを表すのに、 別に bool hasScore を足すか、-1 のような特別な値を「なし」の意味で使うことが多いでしょう。 C# では、int の後ろに ? を付けた int?（null 許容型）を使うと、 普通の int の値に加えて「値がない（null）」も持てる型になります。 

return n.Score ?? 0;

?? は「左が null でなければ左の値、null なら右の値」という演算子です。 n.Score ?? 0 は、「スコアがあればその値、なければ 0」という意味になります。 if (n.Score.HasValue) ... else ... と書くのと同じ結果を、短く書けます。

2.3 取得専用プロパティ: コンストラクタでだけ決める値

public string Id { get; }
public string Label { get; }
public MmKind Kind { get; }
public int? Score { get; } // Leaf のみ
public List<MmNode> Children { get; } = new();

public MmNode(string id, string label, MmKind kind, int? score = null)
{
    Id = id;
    Label = label;
    Kind = kind;
    Score = score;
}

{ get; } だけで set が付いていないプロパティは、取得専用です。 読み出しはできますが、外から書き換えることはできません。値を決められるのは、宣言のところの初期値（Children の = new()）か、 コンストラクタの中だけです。コンストラクタの中でだけは特別に代入が許されていて、Id = id; のように書けます。

試しにコンストラクタの外（別のメソッドの中）で Id = "x"; のように書くと、 error CS0200: Property or indexer 'Foo.Id' cannot be assigned to -- it is read only になります。 「作った後は変えられない」ことが、コンパイラのチェックで保証されます。

Children は取得専用ですが、中身（リストの要素）は変更できます。node.Children.Add(child) はできますが、 node.Children = new List<MmNode>();（Children 自体の差し替え）はできません。 「箱そのものは固定・箱の中身は変えられる」という感覚です。

2.4 再帰 ―― 呼び方は C と同じ

public static int Evaluate(MmNode n)
{
    if (n.Kind == MmKind.Leaf)
        return n.Score ?? 0;

    if (n.Kind == MmKind.Max)
    {
        int best = int.MinValue;
        foreach (var child in n.Children)
            best = Math.Max(best, Evaluate(child));
        return best;
    }

Evaluate の中から Evaluate(child) を呼んでいます。関数が自分自身を呼ぶ再帰で、 書き方も動き方も C の再帰関数と同じです。子が葉ならそこで止まり（if (n.Kind == MmKind.Leaf) return ...;）、 葉でなければ、さらにその子について同じ Evaluate を呼びます。foreach・var は第 9 回のとおりです。

2.5 int.MinValue・double.NegativeInfinity・double.PositiveInfinity

int best = int.MinValue;
…
double best = double.NegativeInfinity;
…
double worstForMax = double.PositiveInfinity;

Math.Min（第 1 回）が「クラス名.関数名」だったのに対して、こちらは「型名.定数名」です。 int.MinValue は int で表せるいちばん小さい値、double.NegativeInfinity・double.PositiveInfinity は （整数にはない）マイナス無限大・プラス無限大です。C の <limits.h> の INT_MIN に近いものですが、 #include はいらず、型の名前からそのまま辿れます。

「まだ 1 つも子を見ていない」ときの初期値として使います。MAX はここから Math.Max で更新していくので、 最初の値はどんな子の評価値より確実に小さい int.MinValue にしておく必要があります。0 などの中途半端な値にすると、 子の評価値がすべて 0 未満だったときに、初期値の 0 が誤って残ってしまいます。

2.6 ローカル関数: メソッドの中に関数を作る

void Collect(MmNode x)
{
    if (x.Kind == MmKind.Leaf) leaves.Add(x.Score ?? 0);
    else foreach (var c in x.Children) Collect(c);
}
Collect(n);

C では、関数の中に別の関数を定義できません。ヘルパーが必要なら、ファイルのトップレベルに別の関数を書き、 必要なデータはポインタ引数やグローバル変数で渡します。C# では、メソッドの中に ローカル関数を書けます。 Collect は AverageLeaf の中だけで使う小さな再帰関数です。

ローカル関数の中からは、外側のメソッドのローカル変数（ここでは leaves）をそのまま使えます（キャプチャ。第 9 回のラムダと同じ仕組み）。 引数でリストを渡し歩く必要がありません。

2.7 LINQ の Sum と (double)leaves.Sum() / leaves.Count

using System.Linq;
…
return leaves.Count == 0 ? 0.0 : (double)leaves.Sum() / leaves.Count;

using System.Linq;（第 1 回の using と同じ意味の書き方）を足すと、 List<int> のようなリストに Sum()・Count() などの拡張メソッドが使えるようになります。 leaves.Sum() は、C で for ループを回して合計するのと同じ結果を 1 つの呼び出しで得られます。

leaves.Sum() と leaves.Count はどちらも int です。(double) のキャスト（第 11 回）を付けずに leaves.Sum() / leaves.Count と書くと、整数どうしの割り算になって小数部分が切り捨てられます（第 1 回の 1 / 60 と同じ落とし穴）。 先に合計だけを (double) にキャストしておくと、割り算全体が小数の割り算になります。三項演算子 ?:（第 11 回）は、 葉が 1 枚もないとき（0 で割ってしまうのを避けるため）の場合分けです。

これまでに出たもの: class・フィールド・メソッド（第 1 回）、List<T>・foreach・var（第 9 回）、 ?:（三項演算子）・(double) のキャスト（第 11 回）。 C と同じもの: if・else、==、コメント //。

3. 計算式とアルゴリズムのポイント

3.1 MAX と MIN の吸い上げ（Evaluate）

if (n.Kind == MmKind.Max)
{
    int best = int.MinValue;
    foreach (var child in n.Children)
        best = Math.Max(best, Evaluate(child));
    return best;
}

// Min
int worstForMax = int.MaxValue;
foreach (var child in n.Children)
    worstForMax = Math.Min(worstForMax, Evaluate(child));
return worstForMax;

式で書くと、MAX の節点は max(子の評価値)、MIN の節点は min(子の評価値) です。 コードでは、それぞれ int.MinValue・int.MaxValue から始めて、子を 1 つ見るごとに Math.Max・Math.Min で更新していきます。 葉に着いたら n.Score ?? 0 をそのまま返します。MAX と MIN のどちらの規則を使うかは、その節点の Kind だけで決まります。 この吸い上げの考え方そのものはくわしい解説の 4 節で図を使って説明しています。

3.2 深さ制限と評価関数（EvaluateWithDepthLimit）

if (n.Kind == MmKind.Leaf)
    return n.Score ?? 0;

if (depthLeft <= 0)
    return useZero ? 0.0 : AverageLeaf(n);

depthLeft（残り深さ）が 0 以下になったら、まだ葉でなくてもそこで探索を打ち切り、評価関数の見積もりを返します。 ここでの評価関数は AverageLeaf: その節点より下にある葉のスコアをすべて集めて、平均を返します。 なぜ 0 固定だと困るかはくわしい解説の 6 節のとおりです。

int ではなく double を使う理由: AverageLeaf は割り算の結果として小数を返すので、EvaluateWithDepthLimit の戻り値も double です。 MAX・MIN の初期値も、int.MinValue・int.MaxValue ではなく double.NegativeInfinity・double.PositiveInfinity を使います。 型を int のままにすると、Math.Max(best, 子の値) の結果（double）を int の変数に入れられません（double → int は狭まる変換で、キャストが要る。第 6 回）。

4. 呼び出してみる（Main と出力）

デモの既定の木（js/maps/minimax-config.js）と同じ形の木を、MmNode を new して組み立てます。 葉は 12 枚、手は L・M・R の 3 つです。 

using System;

public static class Program
{
    public static void Main()
    {
        // 手L の下（応手L1・L2 と葉4枚）
        MmNode l1a = new MmNode("L1a", "葉L1a", MmKind.Leaf, 5);
        MmNode l1b = new MmNode("L1b", "葉L1b", MmKind.Leaf, 3);
        MmNode l1 = new MmNode("L1", "応手L1", MmKind.Max);
        l1.Children.Add(l1a);
        l1.Children.Add(l1b);

        MmNode l2a = new MmNode("L2a", "葉L2a", MmKind.Leaf, 7);
        MmNode l2b = new MmNode("L2b", "葉L2b", MmKind.Leaf, 9);
        MmNode l2 = new MmNode("L2", "応手L2", MmKind.Max);
        l2.Children.Add(l2a);
        l2.Children.Add(l2b);

        MmNode l = new MmNode("L", "手L", MmKind.Min);
        l.Children.Add(l1);
        l.Children.Add(l2);

        // 手M の下
        MmNode m1a = new MmNode("M1a", "葉M1a", MmKind.Leaf, 4);
        MmNode m1b = new MmNode("M1b", "葉M1b", MmKind.Leaf, 2);
        MmNode m1 = new MmNode("M1", "応手M1", MmKind.Max);
        m1.Children.Add(m1a);
        m1.Children.Add(m1b);

        MmNode m2a = new MmNode("M2a", "葉M2a", MmKind.Leaf, 1);
        MmNode m2b = new MmNode("M2b", "葉M2b", MmKind.Leaf, 3);
        MmNode m2 = new MmNode("M2", "応手M2", MmKind.Max);
        m2.Children.Add(m2a);
        m2.Children.Add(m2b);

        MmNode m = new MmNode("M", "手M", MmKind.Min);
        m.Children.Add(m1);
        m.Children.Add(m2);

        // 手R の下
        MmNode r1a = new MmNode("R1a", "葉R1a", MmKind.Leaf, 6);
        MmNode r1b = new MmNode("R1b", "葉R1b", MmKind.Leaf, 8);
        MmNode r1 = new MmNode("R1", "応手R1", MmKind.Max);
        r1.Children.Add(r1a);
        r1.Children.Add(r1b);

        MmNode r2a = new MmNode("R2a", "葉R2a", MmKind.Leaf, 7);
        MmNode r2b = new MmNode("R2b", "葉R2b", MmKind.Leaf, 4);
        MmNode r2 = new MmNode("R2", "応手R2", MmKind.Max);
        r2.Children.Add(r2a);
        r2.Children.Add(r2b);

        MmNode r = new MmNode("R", "手R", MmKind.Min);
        r.Children.Add(r1);
        r.Children.Add(r2);

        // 根（自分の番）
        MmNode root = new MmNode("root", "自分の手番", MmKind.Max);
        root.Children.Add(l);
        root.Children.Add(m);
        root.Children.Add(r);

        int value = Minimax.Evaluate(root);
        Console.WriteLine("Evaluate(root) = " + value);

        double avg = Minimax.EvaluateWithDepthLimit(root, 1, false);
        double zero = Minimax.EvaluateWithDepthLimit(root, 1, true);
        Console.WriteLine("depthLeft=1, 評価関数=平均: " + avg);
        Console.WriteLine("depthLeft=1, 評価関数=0固定: " + zero);
    }
}

実行結果:

Evaluate(root) = 7
depthLeft=1, 評価関数=平均: 6.25
depthLeft=1, 評価関数=0固定: 0
  • Evaluate(root) は根から葉までの全 12 枚を読んで 7 になり、デモを既定のまま再生したときの根の評価値と一致します。
  • depthLeft=1 にすると、根から 1 段先（手L・M・R）までしか読まず、その先は評価関数で見積もります。評価関数を「配下の葉の平均」にすると 6.25、 「0 固定」にすると 3 つの手がすべて 0 になり、区別がつかなくなります。

5. まとめと、やってみよう

この回で出てきた C# の文法です。後の回では、ここへのリンクだけを置きます。

文法ひとことでC では
enum値は型の中。使うとき型名が要る（MmKind.Max）値がそのまま外に出る
int? と ??値がないかもしれない int。なければ既定値特別な値や別の bool で表す
取得専用プロパティ { get; }コンストラクタでだけ決める。以後は変更不可—（普通のメンバー変数）
再帰関数が自分自身を呼ぶC と同じ
int.MinValue など型名.定数名 で最小値・無限大を得るINT_MIN（<limits.h>）
ローカル関数メソッドの中に関数を作る。外の変数を使えるできない（別関数＋引数渡し）
LINQ Sum()リストの合計を 1 呼び出しでfor で合計する

やってみよう

  1. MmNode のコンストラクタの外で Id = "x"; のように書いて、コンパイルエラーの文面を確かめる。
  2. EvaluateWithDepthLimit の depthLeft を 2 や 3 に変えて、7（深さ制限なしの答え）にどれくらいで近づくか試す。

確かめよう

問 1. MmKind.Max のように、型名を付けて書かないといけないのはなぜ？

C# の enum の値は、その型の中に閉じ込められているからです。Max とだけ書いても、コンパイラはどの型の Max か分かりません。

問 2. Score が int? なのはなぜ？

MAX・MIN の節点にはスコアがなく、葉にしかないからです。int? なら「値がない」ことを null で表せます。

問 3. Children は取得専用なのに、なぜ node.Children.Add(child) はできる？

Children というプロパティ自体（箱）は差し替えられませんが、その箱（List<MmNode>）の中身は変更できるからです。
