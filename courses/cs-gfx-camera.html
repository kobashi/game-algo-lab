1. このコードがすること

FollowCamera2D クラスは、プレイヤーを追いかける横スクロールのカメラです。

  • X: カメラの位置（ワールド座標）。
  • Follow: 追従係数（0〜1）。既定値 0.08。
  • DeadZone: デッドゾーンの半幅（px）。既定値 40。
  • Update(playerX, viewW): プレイヤーの位置と画面幅から、1 歩ぶんカメラを動かす。
  • WorldToScreen(wx, wy): ワールド座標をスクリーン座標に変換する。

画面への実際の描画は入っていません。カメラの位置を計算する部分だけを取り出したコードです。

2. 新しく出てくる C# の文法

この回で新しく説明する文法はほとんどありません。ここまでに出てきた書き方の組み合わせで読めます。

2.1 else if の連鎖

if (screenX < mid - DeadZone) desired = playerX - (mid - DeadZone);
else if (screenX > mid + DeadZone) desired = playerX - (mid + DeadZone);

if・else if を並べて、条件を上から順に試す書き方です。C の else if とまったく同じです。 どちらの条件にも当てはまらなければ、直前に代入された desired = X;（変化なし）のままになります。

2.2 名前付きタプルの戻り値 ＋ 式形式メンバー（すでに出てきたものの組み合わせ）

public (float sx, float sy) WorldToScreen(float wx, float wy) =>
    (wx - X, wy);

名前付きタプルを返す書き方は第 1 回、=> で 1 行にまとめる式形式メンバーは 第 3 回で説明しました。ここでは、その 2 つを組み合わせて 「(sx, sy) を返す関数を、{ return … } を書かずに 1 行で書く」形になっています。

これまでに出たもの: public float フィールドと初期値、class（第 1 回）、 名前付きタプル（第 1 回）、式形式メンバー =>（第 3 回）、 float と f サフィックス（第 4 回）。 C と同じもの: if・else if、*・+・-、比較演算子、+=。

3. 計算式とアルゴリズムのポイント

3.1 デッドゾーンの判定

float screenX = playerX - X;
float mid = viewW * 0.5f;
float desired = X;
if (screenX < mid - DeadZone) desired = playerX - (mid - DeadZone);
else if (screenX > mid + DeadZone) desired = playerX - (mid + DeadZone);

まず今のカメラでプレイヤーが画面のどこに映るか（screenX）を求めます。画面の中心 mid から DeadZone だけ離れた範囲（くわしい解説の図 3の黄色い帯）の外に出たときだけ、 「プレイヤーが帯のふちに来る」ようなカメラの目標値 desired を計算します。帯の中にいるあいだは desired = X（今の位置のまま）で、目標は変わりません。

3.2 目標へ少しずつ近づく（追従）

X += (desired - X) * Follow;

desired - X は、今のカメラと目標との差です。この差に Follow（0〜1 の割合）を掛けた分だけ、 1 回の Update でカメラを動かします。Follow が大きいほど早く追い付き、小さいほどゆっくり近づきます （くわしい解説の 4 節）。

3.3 ワールド座標からスクリーン座標へ

public (float sx, float sy) WorldToScreen(float wx, float wy) =>
    (wx - X, wy);

スクリーン x 座標は、ワールド x 座標からカメラの位置を引くだけです（くわしい解説の式と同じ）。 y 座標はカメラで動かしていないので、そのまま返します。

3.4 落とし穴: Follow を 1 より大きくすると

Follow は「1 歩で差の何割を詰めるか」という割合のつもりの数です。1 を超える値を入れるとどうなるか試しました。 Follow = 1.2 にして、画面幅 720、プレイヤーが世界座標 360 → 500（そのまま静止）で動かした結果です。 

frame 1: X=0
frame 2: X=120
frame 3: X=120
frame 4: X=120
frame 5: X=120

2 フレーム目で、差 100 に対して 1.2 倍の 120 だけ動いてしまい、目標の 100 を追い越して止まっています（オーバーシュート）。 たまたま追い越した先がデッドゾーンの中だったので、そのあとは動かなくなりました。Follow は 1 未満で使うものです。

4. 呼び出してみる（Main と出力）

サンプルには実行の入口がないので、次のようなファイルを足して動かします。画面幅 720 で、プレイヤーを 世界座標 360（1 フレーム目）から 500（2〜5 フレーム目は静止）まで動かします。 

using System;

public static class Program
{
    public static void Main()
    {
        FollowCamera2D camera = new FollowCamera2D();
        float viewW = 720f;
        float[] playerXs = { 360f, 500f, 500f, 500f, 500f };

        for (int frame = 1; frame <= playerXs.Length; frame++)
        {
            camera.Update(playerXs[frame - 1], viewW);
            (float sx, float sy) = camera.WorldToScreen(playerXs[frame - 1], 0f);
            Console.WriteLine("frame " + frame + ": X=" + Math.Round(camera.X, 2) + ", screenX=" + Math.Round(sx, 2));
        }
    }
}

実行結果:

frame 1: X=0, screenX=360
frame 2: X=8, screenX=492
frame 3: X=15.36, screenX=484.64
frame 4: X=22.13, screenX=477.87
frame 5: X=28.36, screenX=471.64
  • 1 フレーム目は、プレイヤーがちょうど画面中央（デッドゾーンの中）にいるので、カメラは動きません。
  • 2 フレーム目でプレイヤーが 500 に進むと、デッドゾーンの外に出るのでカメラが動き始めます。
  • プレイヤーが静止したあとも、カメラは目標（デッドゾーンのふち）に向けて少しずつ近づき続けます。
  • Math.Round(camera.X, 2) の camera.X は float ですが、Math.Round(double, int) に渡すため double へ暗黙に変換されています（広がる変換、第 6 回）。

5. まとめと、やってみよう

この回で出てきた文法です。ほとんどが復習なので、リンク先を確認してください。

文法ひとことでC では

やってみよう

  1. Follow を 0.02f に変えて 4 節のコードを動かし、カメラが目標に近づく速さがどう変わるかを確かめる。
  2. Follow を 1.2f に変えて 3.4 節のオーバーシュートを自分の手元でも再現する。

確かめよう

問 1. screenX が mid - DeadZone と mid + DeadZone の間にあるとき、desired はどうなる？

desired = X; のまま変わらないので、カメラは動きません（デッドゾーンの中）。

問 2. WorldToScreen の戻り値の型は？ なぜ 2 つの値をまとめて返す必要がある？

(float sx, float sy) という名前付きタプルです。スクリーン座標は x と y の組なので、2 つの値を 1 回の呼び出しでまとめて返しています。

問 3. Follow = 1.2f のとき、差が 100 だった場合、1 回の Update でカメラはどれだけ動く？

100 × 1.2 ＝ 120 動きます。目標との差（100）より大きく動いてしまうので、目標を追い越します。
