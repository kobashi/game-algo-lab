乱数とシード — くわしい解説

「乱数」に見える数も、じつはコンピュータが決まった計算で作り出しています。 このページでは、その仕組み（疑似乱数）と、同じ出発点から始めれば同じ列になる「シード」の使い方、 LCG という作り方の式と繰り返し（周期）、そして XorShift というもう 1 つの作り方を、図と手計算で説明します。 乱数とシードのデモと合わせて読んでください。

1. 疑似乱数（PRNG）ってなに

コンピュータは、あらかじめ決められた計算しかできません。サイコロのように「本当に何が出るか分からない」数を作ることはできず、 代わりに「今の数から、決まった式で次の数を計算する」ことをくり返して、人の目にはでたらめに見える数の列を作ります。 この仕組みを疑似乱数（PRNG）といいます。

ゲームでは、敵の出現やアイテムの配置、カードの並びなど、いろいろな場面でこの疑似乱数を使います。

2. シードと再現性

PRNG の出発点になる数をシードといいます。 PRNG は「決まった計算」なので、同じシードから始めれば、必ず同じ数の列になります。 これを再現性といいます。

たとえば、デモを標準の PRNG（Mulberry32）でシード 42 にして生成すると、最初の数は 0.6011, 0.4483, 0.8525, 0.6697 … という列になります。もう一度「同じ設定で再生成」しても、まったく同じ列が出ます。 シードを 43 に変えると、0.9998, 0.2764, 0.5294, 0.0591 … という別の列になります。

再現性が役に立つ場面: 同じ初期状態、同じ処理、同じ入力の順で乱数を使うと、ゲームの展開をもう一度作れます。 デモの 1〜6 の出目は、出現する敵の種類として読めます。1 スライム、2 コウモリ、3 ゴブリン、4 オーク、5 ゴーレム、6 ドラゴン。 シード 42 の Mulberry32 では、先頭は 4 オーク、3 ゴブリン、6 ドラゴン、5 ゴーレムです。シードを変えると、この並びが変わります。 対話の分岐を含むリプレイでは、入力の列も同じにします。 考え方はリプレイと決定性のページでも見られます。

3. LCG の式を手計算してみる

いちばん簡単な PRNG の作り方がLCG（線形合同法）です。式はこうです。

次の数 ＝ (a × 今の数 ＋ c) を m（法） で割った余り

a・c・m は好きな数を決めておく定数です。割り算の余りは、必ず 0 から m−1 までの数になります。 小さな数で、実際に手を動かして計算してみましょう。ここでは a = 2、c = 1、m = 5、出発点（シード）を 0 とします。

手順計算結果
X0（シード）—0
X1(2 × 0 ＋ 1) mod 51
X2(2 × 1 ＋ 1) mod 53
X3(2 × 3 ＋ 1) mod 5 ＝ 7 mod 52
X4(2 × 2 ＋ 1) mod 5 ＝ 5 mod 50（＝ X0）

a を 1 に固定した 8 マス。 m=8 で a=1 にすると、1 歩の大きさは c です。最初の数回を手で予想してから、デモで確認します。

4. なぜ同じ列を繰り返す？（周期）

m で割った余りは、0 から m−1 までのm 通りしかありません。 つまり、LCG が今持っている数（状態）は、多くても m 通りしかない、ということです。 計算をずっと続けていくと、有限個の状態しかないのですから、いつか前に一度出てきた数ともう一度出会います。

次の数は「今の数」だけで決まるので、同じ数にもう一度出会うと、そこから先はまったく同じ計算をくり返し、まったく同じ並びが出てきます。 周期は、その繰り返す部分の 1 周の長さです。同じ状態がもう一度出るまでの差を数えます。

出発点がまだ輪の外にある列もあります。そのとき、輪に入るまでの個数は周期に入りません。

提出課題 11 の進め方: 割り当てられた法 m と、シードと、サンプル数を、A と B で同じにします。動かすのは a か c の片方だけです。 動かす前に、短くなる方を予想してから周期パネルで測り、予想と測った理由を書きます。 m が 2 の累乗のときの判定は、発展としてデモの「Hull–Dobell 目安」と Hull・Dobell の原論文 に置けます。課題では、その名前の前に、片方だけ動かして測ります。

5. ヒストグラムで散らばりを見る

PRNG が作る数が、0 から 1 の間にまんべんなく散らばっているかを確かめる方法があります。 0〜1 の範囲をいくつかの区間に分け、それぞれの区間に何個の数が入ったかを、棒の高さで表したグラフです。これを ヒストグラムといいます。

棒が表すのは、その区間に入った個数です。同じ個数なら、並び順が違っても棒は同じです。 周期は周期パネルで読みます。偏りの手掛かりは、同じサンプル数のヒストグラムで見ます。

デモの生成数は最初 48、最大 128 です。法が 256 や 512 のとき、最大周期の 1 周分はヒストグラムに入りきりません。 周期パネルはサンプルとは別に状態をたどるので、生成数を増やさなくても周期は測れます。

小さい m では、全部の状態を決まった順に通る列もあります。a=1, c=1, m=8, シード 0 は、状態が 0→1→2→3→4→5→6→7→0 で、周期は 8 です。 同じ 8 個を別の順に並べても、1 周の出現回数が同じなら棒は同じです。周期、出現回数、順番は、別々に読みます。

6. XorShift：ビット操作で作る乱数

LCG は掛け算・足し算・割り算を使いますが、XorShift は もっと計算が軽い「ビット操作」だけで作る PRNG です。数を 2 進数（0 と 1 の並び）で見て、 ずらす（シフト）操作と、排他的論理和（XOR。同じビットなら 0、違うビットなら 1 になる計算）だけをくり返します。

1 つだけ注意があります。シード 0 は退化してしまい、 XorShift はシードが 0 だと、何回計算しても 0 のまま変わりません。0 と 0 を XOR しても 0 のままだからです。 そのため、実装ではシードが 0 のときは、あらかじめ別の数にずらしてから計算を始めます。

7. まとめ

  • コンピュータの乱数は「疑似乱数」。決まった式で、見た目だけでたらめな数の列を作る
  • 出発点の数をシードという。同じ初期状態、同じ処理、同じ入力の順なら、同じ列になる。1〜6 の出目は敵の種類として読める。対話のリプレイでは入力の列も要る
  • LCG は「次 ＝ (a × 今 ＋ c) を m で割った余り」。周期は、繰り返す部分の 1 周の長さ。状態は m 通りまでなので、周期は m 以下
  • ヒストグラムの棒は出現回数。周期は周期パネル、偏りは同じサンプル数のヒストグラム、順番は別
  • XorShift はビットのシフトと XOR だけで作る。シード 0 は 0 のまま変わらないので、実装ではずらして使う

やってみよう

  1. シード 42 で生成し、1〜6 の出目を敵の種類として読む。「同じ設定で再生成」で、先頭の並びが同じことを確かめる。
  2. シード 43 で生成し、先頭の敵の並びが変わることを見る。
  3. a=1, m=8, シード 0 で、c=1 と c=2 の周期を予想してから開く。c=1 と c=2。
  4. 質が悪い LCG（m=16）で、周期パネルの周期と、同じサンプル数のヒストグラムを分けて見る。
  5. a が悪い（m=256）で、輪の外の数と、周期 1 を見分ける。

確かめよう

問 1. 同じシードで乱数を 2 回生成すると、出てくる数の列はどうなる？

まったく同じ列になります（再現性）。

問 2. LCG で、余り（状態）は何通りある？

m 通り（0 から m−1 まで）です。

問 3. XorShift でシードを 0 にすると、どうなる？

計算しても 0 のまま変わりません（退化）。実装では、0 を別の数にずらしてから使います。

問 4. ヒストグラムの棒が同じなら、出た順番も同じですか？

棒は出現回数です。同じ個数なら、順番が違っても棒は同じです。周期は周期パネルで読みます。

問 5. a=2, c=0, m=256, シード 7 の周期は？

0 に入ったあとの 1 周なので、周期は 1 です。7 から 128 までは輪の外です。
