乱数とシード — くわしい解説

「乱数」に見える数も、じつはコンピュータが決まった計算で作り出しています。 このページでは、その仕組み（疑似乱数）と、同じ出発点から始めれば同じ列になる「シード」の使い方、 LCG という作り方の式と繰り返し（周期）、そして XorShift というもう 1 つの作り方を、図と手計算で説明します。 乱数とシードのデモと合わせて読んでください。

1. 疑似乱数（PRNG）ってなに

コンピュータは、あらかじめ決められた計算しかできません。サイコロのように「本当に何が出るか分からない」数を作ることはできず、 代わりに「今の数から、決まった式で次の数を計算する」ことをくり返して、人の目にはでたらめに見える数の列を作ります。 この仕組みを疑似乱数（PRNG）といいます。

ゲームでは、敵の出現やアイテムの配置、カードの並びなど、いろいろな場面でこの疑似乱数を使います。

2. シードと再現性

PRNG の出発点になる数をシードといいます。 PRNG は「決まった計算」なので、同じシードから始めれば、必ず同じ数の列になります。 これを再現性といいます。

たとえば、デモを標準の PRNG（Mulberry32）でシード 42 にして生成すると、最初の数は 0.6011, 0.4483, 0.8525, 0.6697 … という列になります。もう一度「同じ設定で再生成」しても、まったく同じ列が出ます。 シードを 43 に変えると、0.9998, 0.2764, 0.5294, 0.0591 … という別の列になります。

再現性が役に立つ場面: 同じシードを保存しておけば、ゲームの展開をもう一度そのまま作り直せます。 リプレイ（もう一度同じ動きを見せる機能）や、バグが起きたときにもう一度同じ状況を再現するのに使われます。

3. LCG の式を手計算してみる

いちばん簡単な PRNG の作り方がLCG（線形合同法）です。式はこうです。

次の数 ＝ (a × 今の数 ＋ c) を m（法） で割った余り

a・c・m は好きな数を決めておく定数です。割り算の余りは、必ず 0 から m−1 までの数になります。 小さな数で、実際に手を動かして計算してみましょう。ここでは a = 2、c = 1、m = 5、出発点（シード）を 0 とします。

手順計算結果
X0（シード）—0
X1(2 × 0 ＋ 1) mod 51
X2(2 × 1 ＋ 1) mod 53
X3(2 × 3 ＋ 1) mod 5 ＝ 7 mod 52
X4(2 × 2 ＋ 1) mod 5 ＝ 5 mod 50（＝ X0）

4. なぜ同じ列を繰り返す？（周期）

m で割った余りは、0 から m−1 までのm 通りしかありません。 つまり、LCG が今持っている数（状態）は、多くても m 通りしかない、ということです。 計算をずっと続けていくと、有限個の状態しかないのですから、いつか前に一度出てきた数ともう一度出会います。

次の数は「今の数」だけで決まるので、同じ数に戻れば、そこから先はまったく同じ計算をくり返し、まったく同じ並びが出てきます。 この、繰り返しが始まるまでの長さを周期といいます。

考えてみよう: 法 m の LCG で、周期がちょうど m になる a・c の組はどんな組でしょうか。 デモで a・c・m をいろいろ変えて、周期の表示を見ながら考えてみましょう（提出課題 11 のテーマです）。

5. ヒストグラムで散らばりを見る

PRNG が作る数が、0 から 1 の間にまんべんなく散らばっているかを確かめる方法があります。 0〜1 の範囲をいくつかの区間に分け、それぞれの区間に何個の数が入ったかを、棒の高さで表したグラフです。これを ヒストグラムといいます。

質の良い PRNG なら、どの区間にもだいたい同じくらいの数が入り、棒の高さがそろいます。 質の悪い PRNG だと、まったく数が入らない区間や、逆にたくさん入ってしまう区間ができ、棒の高さがばらばらになります。

6. XorShift：ビット操作で作る乱数

LCG は掛け算・足し算・割り算を使いますが、XorShift は もっと計算が軽い「ビット操作」だけで作る PRNG です。数を 2 進数（0 と 1 の並び）で見て、 ずらす（シフト）操作と、排他的論理和（XOR。同じビットなら 0、違うビットなら 1 になる計算）だけをくり返します。

1 つだけ注意があります。シード 0 は退化してしまい、 XorShift はシードが 0 だと、何回計算しても 0 のまま変わりません。0 と 0 を XOR しても 0 のままだからです。 そのため、実装ではシードが 0 のときは、あらかじめ別の数にずらしてから計算を始めます。

7. まとめ

  • コンピュータの乱数は「疑似乱数」。決まった式で、見た目だけでたらめな数の列を作る
  • 出発点の数をシードという。同じシードなら必ず同じ列になる（再現性）。リプレイやバグの再現に使える
  • LCG は「次 ＝ (a × 今 ＋ c) を m で割った余り」。余りは m 通りしかないので、いつか同じ数に戻り、そこから同じ列を繰り返す（周期）
  • ヒストグラムで、数が 0〜1 にまんべんなく散らばっているかを確かめられる
  • XorShift はビットのシフトと XOR だけで作る。シード 0 は 0 のまま変わらないので、実装ではずらして使う

やってみよう

  1. シード 42 で生成し、「同じ設定で再生成」を押して、まったく同じ列になることを確かめる。
  2. 質が悪い LCG（m=16）で生成し、ヒストグラムの棒の高さと、周期の表示を見る。
  3. XorShift のシードを 0 にして生成し、周期の表示を読む。

確かめよう

問 1. 同じシードで乱数を 2 回生成すると、出てくる数の列はどうなる？

まったく同じ列になります（再現性）。

問 2. LCG で、余り（状態）は何通りある？

m 通り（0 から m−1 まで）です。

問 3. XorShift でシードを 0 にすると、どうなる？

計算しても 0 のまま変わりません（退化）。実装では、0 を別の数にずらしてから使います。
