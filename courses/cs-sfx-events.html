1. このコードがすること

このファイルには、次の 3 つがあります。

  • EventBus: イベント名（文字列）ごとに、呼び出す処理の一覧を持つ。On で登録、Emit で発行する。
  • SfxService: 音を鳴らす係。Muted なら鳴らさない。
  • SfxEventsExample.Main: 両方を組み立てて、Jump・Land・Hit を発行してみる実行例。

発行する側（ゲームの処理）と、鳴らす側（SfxService）が、EventBus を介して分かれているのがポイントです。

2. 新しく出てくる C# の文法

2.1 ジェネリクス List<T>・Dictionary<TKey, TValue>

private readonly Dictionary<string, List<Action>> _handlers = new();

List<T> は、大きさが伸び縮みする配列のようなものです。T のところに、 その List がしまう要素の型（ここでは Action）を書きます。Dictionary<TKey, TValue> は、 キー（ここでは string のイベント名）から値（ここでは List<Action>）を引ける入れ物です。 <…> の中に型を指定して使う仕組みをジェネリクスといいます。

C で近いことをすると

// 型ごとに別の名前の配列・関数を書くか、void* とサイズを自分で管理する

C#（ジェネリクス）

Dictionary<string, List<Action>> handlers;

C には配列の自動拡張や、キーから値を引く仕組みが標準では無いので、自分で確保・拡張・解放を書くか、 型ごとに別々の実装を用意します。C# の List<T>・Dictionary<TKey, TValue> は、 どんな型を入れても、拡張や検索の中身を書き直さずに使い回せます。

2.2 readonly フィールド

private readonly Dictionary<string, List<Action>> _handlers = new();

readonly を付けたフィールドは、宣言のとき（またはコンストラクタの中）でしか代入できません。 _handlers という入れ物そのものを後から別の物に差し替えることは無い、という宣言です （入れ物の中身を Add したり書き換えたりすることはできます）。差し替えようとすると、コンパイルエラーになります。

2.3 Action とラムダ式 () => …

public void On(string ev, Action fn)
bus.On("Jump", () => sfx.PlayTone(440f, 0.08f));

Action は「引数も戻り値も無い処理」を表す型で、関数そのものを値として渡せるようにするものです。 () => sfx.PlayTone(440f, 0.08f) はラムダ式で、「その場で作る名前の無い小さな関数」です。 () が引数（無し）、=> の右が実行する中身です。

C（関数ポインタ）

void jump_sound(void) { play_tone(440, 0.08); }
void (*fn)(void) = jump_sound;
fn();

C#（Action ＋ ラムダ式）

Action fn = () => sfx.PlayTone(440f, 0.08f);
fn();

C の関数ポインタは、あらかじめ名前を付けた関数しか指せません。C# のラムダ式は、その場で処理を書くだけで、 わざわざ別名の関数を用意しなくてよいのが便利なところです。

2.4 ラムダのキャプチャ（外の変数を使う）

bus.On("Jump", () => sfx.PlayTone(440f, 0.08f));

このラムダ式の中の sfx は、ラムダ式の外（Main）で作った変数です。ラムダ式は、自分の外にある変数を そのまま使えます。これをキャプチャといいます。あとで sfx.Muted を変えると、 もう登録し終わったこのラムダ式の動きも変わります（4 節で確認します）。C の関数はこのような「外の変数を覚えておく」仕組みを持ちません。

2.5 foreach

foreach (Action fn in _handlers[ev])
    fn();

foreach は、List などの中身を先頭から順に 1 つずつ取り出すループです。 C の for (int i = 0; i < n; i++) fn(list[i]); のように添字を自分で管理する必要がありません。

2.6 var

var bus = new EventBus();
var sfx = new SfxService();

var は、型を書く代わりに、右辺（new EventBus()）から型を推測してもらう書き方です。 EventBus bus = new EventBus(); と書いたのとまったく同じ意味で、型が変わるわけではありません。 右辺を見れば型が明らかなときによく使われます。

2.7 ContainsKey とインデクサ

if (!_handlers.ContainsKey(ev))
    _handlers[ev] = new List<Action>();
_handlers[ev].Add(fn);

ContainsKey(ev) は、そのキーがすでに入っているかを調べます。_handlers[ev] のように [ ] で書く部分をインデクサといい、配列と同じ書き方でキーから値を読み書きできます。 C の配列の添字アクセスに近い感覚ですが、添字が整数とは限らず、ここでは文字列です。

2.8 string 型（C の char* との違い）

public void On(string ev, Action fn)

C の文字列は char*（文字の配列の先頭アドレス）で、長さは自分で管理し（\0 を探す）、 == は中身ではなくアドレスを比べます。C# の string は、長さを気にしなくてよく、 == は中身（文字の並び）を比べます。また、一度作った string の中身は変更できません （変えたければ新しい string を作ります）。 

string a = "Ju" + "mp";
string b = "Jump";
Console.WriteLine(a == b);   // True（別々に作られても中身が同じなら true）

これまでに出たもの: using System.Collections.Generic;（using は第 1 回）、440f の f サフィックス（第 4 回）、 public sealed class（第 1 回）、bool（第 2 回）。 C と同じもの: if・!・return。

3. 計算式とアルゴリズムのポイント

3.1 登録（On）

if (!_handlers.ContainsKey(ev))
    _handlers[ev] = new List<Action>();
_handlers[ev].Add(fn);

そのイベント名で登録するのが初めてなら、まず空の List を作ってから、Add で処理を追加します。 2 回目以降は、すでにある List にそのまま追加していくので、1 つのイベントに複数の処理を登録できます （くわしい解説の図 2の「あとから購読者を足す」動きです）。

3.2 発行（Emit）

if (!_handlers.ContainsKey(ev)) return;   // 誰も聞いていないイベントは何もしない
foreach (Action fn in _handlers[ev])
    fn();

誰も登録していないイベント名なら、何もせずに戻ります。登録があれば、foreach で 1 つずつ順番に呼び出します。 Emit 自身は、呼び出す処理の中身（音を鳴らすのか、画面を揺らすのか）をまったく知りません。

3.3 落とし穴: ContainsKey を確かめずにインデクサを使うと

_handlers[ev] は、キーが無いとどうなるか試しました。登録の無いキーでいきなり読み出すと、例外で止まります。 

Dictionary<string, List<Action>> handlers = new();
List<Action> list = handlers["Foo"];   // "Foo" は登録していない
// Unhandled exception: System.Collections.Generic.KeyNotFoundException:
// The given key 'Foo' was not present in the dictionary.

Emit や On が先に ContainsKey で確かめているのは、この例外を避けるためです。

4. 呼び出してみる（Main と出力）

このサンプルには SfxEventsExample.Main という実行の入口がすでにあるので、そのまま動かします。 

var bus = new EventBus();
var sfx = new SfxService();

// イベントと音の対応（デモの既定値）。ゲーム側は音を知らなくてよい
bus.On("Jump", () => sfx.PlayTone(440f, 0.08f));
bus.On("Land", () => sfx.PlayTone(180f, 0.1f));
bus.On("Hit", () => sfx.PlayTone(120f, 0.12f));

bus.Emit("Jump");   // ゲーム側は「ジャンプした」と知らせるだけ
bus.Emit("Land");
sfx.Muted = true;
bus.Emit("Hit");    // イベントは起きるが、音は鳴らない

実行結果:

Emit Jump
  play 440 Hz, 0.08 s
Emit Land
  play 180 Hz, 0.1 s
Emit Hit
  • Jump・Land は、登録した処理が呼ばれて音が鳴っています（Emit の行のあとに play の行）。
  • Hit の前に sfx.Muted = true; としたので、Emit "Hit" の行だけが出て、play の行が出ていません。 bus.On("Hit", …) のラムダ式は sfx をキャプチャしているので、あとから Muted を変えると、 すでに登録済みのこのラムダ式の結果も変わります（2.4 節）。
  • 誰も登録していないイベント名（例えば "Pickup"）を Emit しても、Emit … の行が出るだけで、エラーにはなりません（試して確認済み）。

5. まとめと、やってみよう

この回で出てきた C# の文法です。後の回では、ここへのリンクだけを置きます。

文法ひとことでC では
List<T>・Dictionary<K,V>型を指定して使う、伸び縮みする配列・キーで引ける入れ物無い（自分で配列やハッシュ表を書く）
readonly宣言時かコンストラクタでしか代入できないフィールドconst に近いが、フィールド単位
Action・ラムダ式 () => …処理そのものを値として渡す関数ポインタ（名前が要る）
キャプチャラムダ式が外の変数を覚えて使う無い
foreach要素を順番に取り出すループfor ＋ 添字
var右辺から型を推測してもらう無い（型を書く必要がある）
ContainsKey・インデクサ [ ]キーがあるか調べる・キーで読み書きする配列の添字アクセスに近い
string長さを気にしない。== は中身を比較。変更できないchar*（アドレス比較、長さは自己管理）

やってみよう

  1. 4 節の呼び出し例に、bus.On("Jump", () => Console.WriteLine(" flash!")); をもう 1 行足して、1 つのイベントに 2 つの処理を登録し、両方呼ばれることを確かめる。
  2. 3.3 節の例をまねて、登録していないキーを Dictionary のインデクサでいきなり読み出し、同じ例外が出ることを自分の手元でも確かめる。

確かめよう

問 1. bus.On("Jump", () => sfx.PlayTone(440f, 0.08f)); の sfx は、どこで作られた変数？

Main の中で作られたローカル変数です。ラムダ式がそれをキャプチャして使っています。

問 2. sfx.Muted = true; のあとに bus.Emit("Hit") を呼ぶと、Emit Hit の行は出る？ play の行は？

Emit Hit は出ます（発行そのものは止まらない）。play の行は出ません（PlayTone の中で Muted を見て鳴らさないため）。

問 3. _handlers.ContainsKey(ev) を確かめずに _handlers[ev] を読むと、キーが無いときどうなる？

KeyNotFoundException という例外が発生して、プログラムが止まります。
