1. この解説シリーズの読み方

入門コースの 14 本のトピックには、それぞれ C# のサンプルコードがあります。この解説は 1 から 14 まで順に読む前提で書いています。 C# の文法は、初めて出てきた回でだけ説明します。2 回目からは「第 1 回」のようにリンクだけを置くので、忘れたときはそこへ戻ってください。

C# は、C と同じく if・for・while・+=・++・&& などを使います。 文の終わりの ;、ブロックの { }、// のコメントも同じです。 大きく違うのは、データと関数を「クラス」にまとめて書くことと、メモリを自分で解放しなくてよいことです（使われなくなったものは、実行環境が自動で片付けます）。

自分のパソコンで動かすには: .NET SDK を入れて dotnet new console でプロジェクトを作り、サンプルのファイルを入れて dotnet run します。 入門コースのサンプルの多くは「部品」だけで、実行の入口（Main）がありません。5 節のように、呼び出す側のコードを足して動かします。

2. このコードがすること

このファイルには、次の 3 つがあります。

  • BallWorld: 床で跳ねるボール。Update(dt) で、時間 dt 秒ぶん動かします。
  • GameLoopExample.VariableStep: 可変 timestep。そのフレームにかかった時間で 1 回だけ更新します。
  • GameLoopExample.FixedStep: 固定 timestep。たまった時間（アキュムレータ）から、決まった長さずつ何回か更新します。

描画やボタンなどの画面の部分は入っていません。ゲームの「中身の計算」だけを取り出したコードです。

3. 新しく出てくる C# の文法

3.1 using System; と Math

using System;

C の #include <math.h> に似ていますが、ファイルを取り込むのではありません。 C# の部品は「名前空間」という名前のグループに入っていて、using System; と書くと、System グループの名前を短く書けるようになります。 書かないと、Math.Min を System.Math.Min と書く必要があります。 

double dt = Math.Min(realDtSeconds, 0.1);

Math は数学の関数をまとめたクラスで、Math.Min（小さいほう）、Math.Abs（絶対値）などを「クラス名.関数名」の形で呼びます。 C の fmin・fabs のように型ごとに名前を変える必要はなく、int でも double でも同じ Math.Min が使えます。

3.2 クラス: データと関数をまとめる

C では、構造体と、それを受け取る関数を別々に書きます。C# では、データ（フィールド）と関数（メソッド）を 1 つの class の中に書きます。

C で書くと

struct BallWorld {
    double y, v;
    double gravity;
};

void ball_update(struct BallWorld *w, double dt)
{
    w->v += w->gravity * dt;
    w->y += w->v * dt;
}

C# のサンプル（抜き出し）

public sealed class BallWorld
{
    public double Y;      // 上=0、下へ正
    public double V;
    …
    public void Update(double dtSeconds)
    {
        V += Gravity * dtSeconds;
        Y += V * dtSeconds;

C# の Update の中では、w->V のような書き方をせず、フィールド名 V をそのまま書きます。 「今この関数を呼び出されているボール自身」のフィールドを指します（C# ではこのボール自身を this と呼び、this.V とも書けます）。 呼び出す側は world.Update(0.016); のように「変数.メソッド名(引数)」と書きます。

3.3 フィールドの初期値

public double Gravity = 8;  // 座標は 0..1.15 に正規化（床 = 1.0）
public double Floor = 1.0;
public double Restitution = 0.72;

C の構造体のメンバーには、宣言のところで初期値を書けません。C# のクラスでは、フィールドに = 8 のように初期値を書けます。 初期値を書かなかったフィールド（Y・V）は、自動で 0 になります。C のように「初期化し忘れてゴミの値が入っている」ことはありません。 C# では、関数の中のローカル変数も、値を入れる前に読むとコンパイルエラーになります。

3.4 public・sealed・static class

  • public: クラスの外から使ってよい、という印です。フィールドやメソッドに付けないと、そのクラスの中からしか使えません（くわしくは第 6 回）。
  • sealed: このクラスをもとにした別のクラス（派生クラス）を作らせない、という印です。入門コースの範囲では「付いていても気にしなくてよい」ものです。
  • static class: 関数だけを入れる入れ物です。GameLoopExample はデータを持たないので、C の「ただの関数の集まり」に近いものです。呼ぶときは GameLoopExample.VariableStep(...) のようにクラス名を前に付けます。
public static class GameLoopExample
{
    …
    public static void VariableStep(BallWorld world, double realDtSeconds)

3.5 クラスの変数は「参照」— C のポインタに近い

public static void VariableStep(BallWorld world, double realDtSeconds)
{
    …
    world.Update(dt);
}

ここは C と大きく違うので注意してください。BallWorld のようなクラスの変数には、ボールそのものではなく、ボールの場所（参照）が入っています。 引数で world を渡すと、場所がコピーされるだけで、ボールは 1 つのままです。だから VariableStep の中で world.Update すると、呼び出した側のボールが動きます。 C で言えば struct BallWorld *world を渡したのと同じ動きですが、* や -> は書きません。

クラスのオブジェクトは new で作ります（BallWorld world = new BallWorld();）。C の malloc に似ていますが、free はいりません。 値がそのままコピーされる型（C の構造体に近いもの）は第 3 回で出てきます。

3.6 /// のコメント

/// <summary>可変 timestep: そのフレームの realDt で 1 回だけ更新。</summary>

/// で始まるコメントは「ドキュメントコメント」です。<summary> の中にメソッドの説明を書くと、開発環境でそのメソッドにマウスを乗せたときに説明が出ます。 プログラムの動きには関係しません。ふつうのコメントとして読んでかまいません。

3.7 タプル: 2 つの値をまとめて返す

public static (double accumulator, int steps) FixedStep(
…
    return (accumulator, steps);

C の関数は値を 1 つしか返せないので、2 つ返したいときは構造体を作るか、ポインタ引数に書き込みます。 C# では (double accumulator, int steps) のように、値の組（タプル）を戻り値の型にできます。 return (accumulator, steps); で 2 つの値をまとめて返します。

受け取る側は、(double left, int steps) = GameLoopExample.FixedStep(...); のように、かっこの中に変数を並べて一度に受け取れます（5 節で使います）。 まとめたまま受け取って r.steps のように名前で取り出すこともできます。

3.8 ref 引数: 呼び出し元の変数を書き換える

ref double accumulator,
…
accumulator += Math.Min(realDtSeconds, 0.25);

double や int の引数は、C と同じく値がコピーされて渡されます。関数の中で書き換えても、呼び出し元の変数は変わりません。 ref を付けると、呼び出し元の変数そのものを書き換えられます。C の double *accumulator と *accumulator += ... に当たります。

C

fixed_step(&world, dt, fixed, &acc, 5);

C#（呼ぶ側にも ref を書く）

GameLoopExample.FixedStep(world, dt, fixedDt, ref acc, 5);

呼ぶ側にも ref と書くので、「この呼び出しで acc が書き換わる」ことが見ただけで分かります。 なお world はクラス（3.5 の参照）なので、ref を付けなくても中身は書き換わります。

C と同じもの: double・int、while・if、+=・-=・++、>=・<・&&、単項の -。

4. 計算式とアルゴリズムのポイント

4.1 1 回の更新（Update）

V += Gravity * dtSeconds;
Y += V * dtSeconds;
if (Y + Radius > Floor)
{
    Y = Floor - Radius;
    V = -Math.Abs(V) * Restitution;
}
  • 式で書くと v ← v + g·Δt、そのあと y ← y + v·Δt です。先に速さを変え、変えたあとの速さで進みます。この順番のせいで、Δt が大きいと結果が変わります（くわしい解説の 4 節）。
  • y は下向きが正です。ボールの下の端 Y + Radius が床 Floor を越えたら、床の上に置き直します（めり込みの修正）。
  • 速さは -Math.Abs(V) * Restitution にします。Abs で向きに関係なく大きさを取り、マイナスを付けて必ず上向きにしてから、反発係数 0.72 を掛けて小さくします。-V * Restitution と書くと、すでに上向きだったときに下向きに戻ってしまいます。

4.2 可変 timestep（VariableStep）

double dt = Math.Min(realDtSeconds, 0.1);
world.Update(dt);

かかった時間 realDt で 1 回だけ更新します。Math.Min(…, 0.1) で 0.1 秒より長い時間は 0.1 秒に切り詰めます。 別のタブから戻ったときなど、何秒もたってから 1 フレームが来ると、ボールが一気に床を突き抜けてしまうからです。

4.3 固定 timestep（FixedStep）

accumulator += Math.Min(realDtSeconds, 0.25);
int steps = 0;
while (accumulator >= fixedDtSeconds && steps < maxSteps)
{
    world.Update(fixedDtSeconds);
    accumulator -= fixedDtSeconds;
    steps++;
}
  1. かかった時間をアキュムレータ（貯金箱）に足します。ここでも 0.25 秒で切り詰めます。
  2. 貯金が fixedDtSeconds 以上ある間、その長さで 1 回更新し、貯金から引きます。1 回の更新の長さはいつも同じです。
  3. steps < maxSteps で、1 フレームの更新回数に上限を付けます。更新が重いときに、回数が増え続ける（スパイラル・オブ・デス）のを防ぎます。
  4. 残った貯金（fixedDtSeconds 未満）は、次のフレームに持ち越します。
戻り値と ref の関係: accumulator は ref なので、呼び出し元の変数はすでに書き換わっています。戻り値のタプルに入っている accumulator も同じ値です。 説明のために両方で返していますが、実際のゲームではどちらか一方にするのがふつうです。

5. 呼び出してみる（Main と出力）

サンプルには実行の入口がないので、次のようなファイルを足して動かします。1 フレームに 41.7 ms かかる状態を 3 フレームぶん、固定 timestep（1 回 1/60 秒、上限 5 回）で進めます。 

using System;

public static class Program
{
    public static void Main()
    {
        BallWorld world = new BallWorld();   // Y と V は 0 から始まる
        double acc = 0;

        for (int frame = 1; frame <= 3; frame++)
        {
            (double left, int steps) = GameLoopExample.FixedStep(world, 0.0417, 1.0 / 60, ref acc, 5);
            Console.WriteLine("frame " + frame + ": steps=" + steps + ", acc=" + Math.Round(left, 4));
        }
    }
}

実行結果:

frame 1: steps=2, acc=0.0084
frame 2: steps=3, acc=0.0001
frame 3: steps=2, acc=0.0084
  • static void Main() が実行の入口です（C の int main(void)）。どれか 1 つのクラスの中に書きます。
  • Console.WriteLine は 1 行を表示して改行します（C の printf ＋ \n）。
  • 文字列と数を + でつなぐと、数が文字列に変わってつながります。C の %d のような書式指定はいりません。
  • Math.Round(left, 4) は小数第 4 位までに丸めます。
  • 1.0 / 60 は C と同じく小数の割り算です。1 / 60 と書くと整数の割り算で 0 になるのも C と同じです。

更新の回数が 2 → 3 → 2 と変わり、貯金の残りが次のフレームへ持ち越されているのが分かります。 くわしい解説の「貯金箱」の図と同じ動きです。

やってみよう

  1. 5 節の 0.0417 を 1.0 / 60 にすると、各フレームの steps はいくつになるか予想してから確かめる。
  2. V = -Math.Abs(V) * Restitution; を V = -V * Restitution; に変えたとき、どんな場合に困るかを考える。

確かめよう

問 1. FixedStep の中で accumulator を書き換えると、呼び出し元の acc も変わるのはなぜ？

ref 引数だからです。ref を付けると、値のコピーではなく、呼び出し元の変数そのものが渡されます。

問 2. VariableStep に world を渡すと、呼び出し元のボールが動くのはなぜ？ ref は付いていないのに。

BallWorld はクラスで、変数に入っているのはボールの場所（参照）だからです。場所がコピーされても、指しているボールは同じ 1 つです。

問 3. public double V; に初期値を書いていないとき、最初の値は？

0 です。クラスのフィールドは、初期値を書かなければ自動で 0 になります。
