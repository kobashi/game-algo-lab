1. このコードがすること

盤面を 9 文字の string（'.' が空きマス、'X'・'O' が石）として表し、次のものを用意しています。

  • CurrentPlayer・LegalMoves・Apply: 手番を求める・打てるマスを列挙する・1 手打った後の盤面を作る。
  • Winner・IsTerminal・TerminalValue: 勝敗の判定と、手番から見た終局値。
  • TransformIndex・TransformBoard・Canonical: 盤面の回転・裏返し 8 通りと、その代表値。
  • Solve: negamax（α-β・メモ化・対称性除去を on/off できる）で、盤面の値を求める本体。

ここまでの第 12 回・第 13 回は、あらかじめ用意した木を読みました。 このファイルは、盤面のルールに従ってその場で木を作りながら探索します。考え方はくわしい解説に譲り、 ここではコードとの対応に絞って説明します。

2. 新しく出てくる C# の文法

2.1 ジャグ配列 int[][] と new[] { … }

private static readonly int[][] Lines =
{
    new[] { 0, 1, 2 }, new[] { 3, 4, 5 }, new[] { 6, 7, 8 },
    new[] { 0, 3, 6 }, new[] { 1, 4, 7 }, new[] { 2, 5, 8 },
    new[] { 0, 4, 8 }, new[] { 2, 4, 6 },
};

C の 2 次元配列 int lines[8][3] は、8×3 個の要素が一続きのメモリに並んだ「長方形」です。 C# の int[][] は違います。要素 1 つ 1 つが int[]（配列）で、その配列をさらに 8 個集めた「配列の配列」です。 ジャグ配列と呼ばれ、各行の長さが違ってもかまいません（このコードでは全部 3 個ですが）。

C で書くと

int lines[8][3] = {
    {0,1,2}, {3,4,5}, {6,7,8},
    ...
};

C#（ジャグ配列）

int[][] lines = {
    new[] { 0, 1, 2 }, ...
};

new[] { 0, 1, 2 } は「要素の型は書かなくてよい配列」の作り方です。中身の 0, 1, 2 が全部 int なので、 コンパイラが new int[] { 0, 1, 2 } だと判断してくれます。

2.2 static readonly: 参照は固定、中身は書き換えられる

readonly フィールド自体は第 9 回で出てきました。Lines は static（クラスに 1 つだけ）でもあり、 private static readonly int[][] Lines = ... と両方付いています。ここで注意したいのは、readonly が止めているのは 「配列という参照そのものの差し替え」だけだ、ということです。

試しに、このクラスのメソッドの中で Lines = new int[][] { ... }; のように 差し替えようとすると、 error CS0198: A static readonly field cannot be assigned to (except in a static constructor or a variable initializer) になります。 いっぽう、Lines[0][0] = 9; のように 中身の要素を書き換えるのはコンパイルが通ります。 第 12 回の Children（取得専用プロパティ）の「箱は固定・中身は変えられる」と同じ感覚です。

2.3 char・文字リテラルと、string は変更できない

public static char? Winner(string board)
{
    foreach (var line in Lines)
    {
        char a = board[line[0]], b = board[line[1]], c = board[line[2]];
        if (a != '.' && a == b && b == c) return a;
    }
    return null;
}

char は 1 文字を表す型で、'.'・'X' のように '（シングルクォート）で書きます。C の char と同じです。 board[line[0]] のように、string は添字（[ ]）で 1 文字を取り出せます。ここまでは C の文字配列に近い感覚です。 

public static string Apply(string board, int index, char piece)
{
    var chars = board.ToCharArray();
    chars[index] = piece;
    return new string(chars);
}

違うのは、C# の string は 作った後は 1 文字も書き換えられない（不変）ことです。 試しに string s = "abc"; s[0] = 'X'; と書くと、error CS0200: Property or indexer 'string.this[int]' cannot be assigned to -- it is read only になります。 Apply が 1 手進めた盤面を作るときは、ToCharArray() で書き換え可能な char[] にコピーしてから 1 マスだけ変え、 new string(chars) でその char[] から新しい string を作り直しています。元の board はそのまま残ります。

2.4 new string('.', 9): 同じ文字を並べた文字列

string empty = new string('.', 9);

new string(文字, 個数) は、その文字を指定した個数だけ並べた文字列を作るコンストラクタです。 C で memset(buf, '.', 9) とするのに近いですが、string は不変なので、はじめから欲しい中身をまとめて作ります。

2.5 IEnumerable<int> と yield return

public static IEnumerable<int> LegalMoves(string board)
{
    for (int i = 0; i < board.Length; i++)
        if (board[i] == '.') yield return i;
}

C で「打てるマスの一覧」を返すには、配列とその個数を一緒に返すか、呼び出し側にポインタとバッファを渡してもらう必要があります。 C# では、戻り値の型を IEnumerable<int>（int を順番に取り出せるもの）にして、 return i; の代わりに yield return i; と書くと、呼び出し側が foreach で 1 つずつ受け取れる「値を作る関数」になります。

yield return のたびに、いったん関数の実行がそこで止まり、呼び出し側が次の値を求めたときに続きから再開します。 全部のマスをあらかじめ配列にためてから返すのではなく、foreach (int m in LegalMoves(board))（3 節）のように、 必要になった分だけその場で作ります。

2.6 record（位置指定）

public sealed record SolveOptions(bool AlphaBeta, bool Memo, bool Symmetry);

public sealed record MemoEntry(int Value, char Flag); // 'e'=exact, 'l'=lower, 'u'=upper

record は class の仲間で、「複数の値をひとまとめにして持ち歩く」ためによく使われます。 record SolveOptions(bool AlphaBeta, bool Memo, bool Symmetry) と書くだけで、AlphaBeta・Memo・Symmetry という 3 つの取得専用プロパティと、それを受け取るコンストラクタが自動で作られます（第 12 回で 1 つずつ手で書いた { get; } とコンストラクタを、まとめて生成してくれるイメージです）。

class と違うのは、中身の値が同じであれば == で等しいと判定される点です（class は、既定では中身でなく「同じ実体か」を比べます）。 このコードでは new SolveOptions(AlphaBeta: true, Memo: true, Symmetry: true)（名前付き引数・第 8 回）のように、まとめて設定を渡すのに使っています。

2.7 文字列補間 $"..."

Console.WriteLine($"Solve(empty) = {value} (0=引き分け)"); // 0

ここまでは "frame " + frame + ": steps=" + steps（第 1 回）のように、文字列と値を + でつないできました。 文字列の頭に $ を付けると、{ } の中に変数や式をそのまま書けます。$"Solve(empty) = {value} ..." は、 "Solve(empty) = " + value + " ..." と同じ意味です。+ をいくつも並べるより、出来上がる文字列の形が見た目でも分かりやすくなります。

2.8 string.CompareOrdinal: 文字列の大小を比べる

if (best == null || string.CompareOrdinal(t, best) < 0) best = t;

C の strcmp と同じように、string.CompareOrdinal(a, b) は a が b より小さければ負の数、大きければ正の数、 同じなら 0 を返します。C# の string は <・> で直接は比べられないので、この専用のメソッドを使います （Ordinal は「文字コードの順で比べる」という意味です。言語ごとの辞書の並び順は使わないので、どの環境でも同じ結果になります）。

2.9 参照型の null: 「まだ何もない」を表す

string best = null;

string はクラスと同じ参照型（第 1 回）なので、変数には null（何も指していない）を入れられます。 C の char *p = NULL; に近い感覚ですが、int のような値型はそのままでは null にできません （値がないかもしれないことを表すには int?・第 12 回が必要でした）。 Canonical はここから始めて、8 通りを順に比べながら、いちばん小さいものへ best を書き換えていきます。

これまでに出たもの: class・フィールド・メソッド（第 1 回）、式形式メンバー =>（第 3 回）、 名前付き引数（第 8 回）、List<T>・Dictionary<TKey,TValue>・foreach・var・ラムダ（第 9 回）、LINQ（board.Count(c => c == 'X') の Count。第 12 回）、 TryGetValue と out var（第 10 回）、条件演算子 ?:（第 11 回）、 enum・int?・取得専用プロパティ（第 12 回）。 C と同じもの: for、break、比較演算子。

3. 計算式とアルゴリズムのポイント

3.1 negamax: 1 つの関数で両者を扱う

char mover = CurrentPlayer(board);
int best = int.MinValue;
foreach (int m in LegalMoves(board))
{
    string child = Apply(board, m, mover);
    int v = -Solve(child, -beta, -alpha, opt, memo);
    if (v > best) best = v;
    if (opt.AlphaBeta)
    {
        if (best > alpha) alpha = best;
        if (alpha >= beta) break; // 枝刈り
    }
}

第 12 回・第 13 回の Evaluate は、MAX と MIN で別々の分岐を書いていました。 Solve はどちらの手番でも同じコードを 1 回だけ通ります。仕組みは、子（相手の手番）を Solve(child, -beta, -alpha, ...) のように 符号を反転した窓で呼び、返ってきた値も -Solve(...) と符号を反転させることです。 「相手にとっての最善」を「自分にとっての最悪」として、マイナスを付けるだけで読み替えています。alpha・beta の更新と if (alpha >= beta) break; による枝刈りは、第 13 回の β カット・α カットと同じ考え方です。

3.2 終局値: 手番から見て 1・0・−1

/// <summary>終局値。手番から見て 1=勝ち, 0=引き分け, -1=負け。</summary>
public static int TerminalValue(string board) => Winner(board) != null ? -1 : 0;

コメントには「1=勝ち」ともありますが、TerminalValue のコードが返すのは -1 か 0 だけです。 三目並べは 1 手ごとに手番が交代するので、「今、手番の人から見て盤面が終わっている」のは、直前に相手が 3 つ並べたときだけです。 自分が今まさに 3 つ並べて手番が回ってくることはないので、終局のときの評価は「負け（−1）」か「引き分け（0）」のどちらかにしかなりません。

3.3 メモ化: exact・lower・upper の 3 つのフラグ

int alphaOrig = alpha;
string key = null;
if (opt.Memo)
{
    key = opt.Symmetry ? Canonical(board) : board;
    if (memo.TryGetValue(key, out var entry))
    {
        if (entry.Flag == 'e') return entry.Value;
        if (entry.Flag == 'l' && entry.Value >= beta) return entry.Value;
        if (entry.Flag == 'u' && entry.Value <= alpha) return entry.Value;
        if (opt.AlphaBeta)
        {
            if (entry.Flag == 'l' && entry.Value > alpha) alpha = entry.Value;
            if (entry.Flag == 'u' && entry.Value < beta) beta = entry.Value;
        }
    }
}
if (opt.Memo)
{
    char flag = best <= alphaOrig ? 'u' : best >= beta ? 'l' : 'e';
    memo[key] = new MemoEntry(best, flag);
}

α-β 法は、枝刈りをした節点の値を「正確な値」ではなく「これ以上（下限）」・「これ以下（上限）」としてしか知りません。 値だけをそのままキャッシュすると、次に別の窓（別の alpha・beta）で同じ局面を調べたときに、 下限・上限でしかない値を正確な値と取り違えてしまいます。そこで MemoEntry には、値と一緒に 'e'（exact・正確）・'l'（lower・下限）・'u'（upper・上限）のフラグを保存し、 フラグに応じて「そのまま返してよいか」「窓を狭めるだけに使うか」を使い分けています。

3.4 対称性: 8 通りの変換と Canonical

public static int TransformIndex(int i, int k)
{
    int r = i / 3, c = i % 3;
    if (k >= 4) { c = 2 - c; k -= 4; }
    for (int t = 0; t < k; t++)
    {
        int nr = c, nc = 2 - r;
        r = nr; c = nc;
    }
    return r * 3 + c;
}
public static string Canonical(string board)
{
    string best = null;
    for (int k = 0; k < 8; k++)
    {
        string t = TransformBoard(board, k);
        if (best == null || string.CompareOrdinal(t, best) < 0) best = t;
    }
    return best;
}

TransformIndex(i, k) は、マス i が k 番目の変換（回転・裏返しの組み合わせ、全 8 通り）でどこへ移るかを計算します。 Canonical は、8 通りすべてに変換した盤面を作り、string.CompareOrdinal でいちばん小さい（辞書順で先頭に来る）ものを選びます。 回転・裏返しで見た目が違うだけの盤面は、この代表値がすべて同じになるので、メモ化の key として使うと、まとめて 1 つの局面として扱えます。 8 通りの変換そのものの図はくわしい解説の 5 節にあります。

4. 呼び出してみる（Main と出力）

このサンプルには、すでに実行の入口（Main）が入っています。空盤から、α-β・メモ化・対称性除去をすべて有効にして解析します。 

public static void Main()
{
    var opt = new SolveOptions(AlphaBeta: true, Memo: true, Symmetry: true);
    var memo = new Dictionary<string, MemoEntry>();
    string empty = new string('.', 9);
    int value = Solve(empty, int.MinValue + 1, int.MaxValue - 1, opt, memo);
    Console.WriteLine($"Solve(empty) = {value} (0=引き分け)"); // 0
}

実行結果:

Solve(empty) = 0 (0=引き分け)
  • 空盤から完全に読み切ると、値は 0（引き分け）になります。お互いが最善を尽くすと、どちらも勝てないという意味です。
  • Solve の最初の呼び出しは alpha = int.MinValue + 1・beta = int.MaxValue - 1 です。 int.MinValue（第 12 回）そのものではなく 1 ずらしているのは、Solve の中で -alpha・-beta と 符号を反転する箇所があり、int.MinValue をそのまま反転しようとすると int の表せる範囲を超えてしまう（オーバーフローする）ためです。

やってみよう

  1. Lines[0][0] = 9; と、Lines = new int[][] { }; を試して、どちらがコンパイルエラーになるか確かめる。
  2. SolveOptions を record ではなく普通の class（第 12 回の書き方）で書き直し、同じように動くことを確かめる。

確かめよう

問 1. string の中身を 1 文字だけ変えたいとき、どうする？

ToCharArray() で char[] にコピーし、その要素を書き換えてから、new string(chars) で新しい string を作ります。元の string は変わりません。

問 2. negamax で、子を呼ぶときに符号を反転させる（-Solve(...)）のはなぜ？

相手の手番にとっての最善は、自分にとっては最悪だからです。符号を反転させることで、MAX 用・MIN 用の 2 つの分岐を書かずに、1 つの関数で両方の手番を扱えます。

問 3. メモ化で、値だけでなくフラグ（exact/lower/upper）も保存するのはなぜ？

α-β 法で枝刈りした節点の値は、正確な値ではなく下限・上限でしかないことがあるからです。フラグがないと、別の探索窓で読んだときに、不正確な値を正確な値と取り違えてしまいます。
