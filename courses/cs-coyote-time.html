1. このコードがすること

CoyoteJump クラスは、足場を離れてからの短い猶予のあいだもジャンプを受け付ける仕組みを持っています。

  • CoyoteSeconds: 猶予の長さ（秒）。既定値は 0.12。
  • _coyoteLeft: 猶予タイマーの残り（秒）。
  • Grounded: 接地しているかどうか。呼び出す側が毎フレーム設定します。
  • Update(dt): 1 フレームぶん、タイマーを進める（接地中は満タンに戻し、空中では減らす）。
  • TryJump(jumpPressedEdge, useCoyote): ジャンプを試す。接地中か、猶予が残っていれば成功します。

入力の読み取りや、実際にキャラを飛ばす処理は入っていません。判定の部分だけを取り出したコードです。

2. 新しく出てくる C# の文法

2.1 自動実装プロパティ { get; set; }

public float CoyoteSeconds { get; set; } = 0.12f;

C で書くと

typedef struct {
    float coyote_seconds;
} CoyoteJump;

float coyote_get_seconds(const CoyoteJump *j) { return j->coyote_seconds; }
void coyote_set_seconds(CoyoteJump *j, float v) { j->coyote_seconds = v; }

C#（自動実装プロパティ）

public float CoyoteSeconds { get; set; } = 0.12f;

{ get; set; } と書くと、値を読む（get）・書く（set）ための仕組みを、フィールドと同じ見た目のまま用意してくれます。 これを自動実装プロパティといいます。裏では、値をしまう場所と、それを読み書きする 2 つの小さな関数が自動で作られています。 = 0.12f; は、フィールドと同じように書ける初期値です（f サフィックスは第 4 回）。

呼び出す側は jump.CoyoteSeconds のように、ふつうのフィールドと同じ書き方で読み書きできます。 C のようにゲッター・セッター関数を自分で呼ぶ必要はありません。

2.2 フィールドとプロパティの違い

float _coyoteLeft;
public bool Grounded { get; set; }

_coyoteLeft はただのフィールドです。値が入る場所そのもので、初期値を書かなければ既定値（float なら 0）になります（第 1 回）。 いっぽう Grounded は 2.1 と同じプロパティです。初期値を書いていないので、既定値 false から始まります。

外から見ると、フィールドもプロパティも jump.Grounded = true; のように同じ書き方で使えます。ちがうのは中身で、 プロパティは実際には get/set の関数を呼んでいます。あとから「値を設定するときに 0 未満を弾く」のような処理を足したくなっても、 プロパティなら呼び出す側のコードを変えずに済みます（フィールドのままだと書き換えられません）。

2.3 アクセス修飾子の省略は private・_ で始まる名前

float _coyoteLeft;

第 1 回で、public を付けると外から使える、と説明しました。_coyoteLeft には public も private も付いていません。C# では、修飾子を省略すると自動的に private（このクラスの中からしか使えない）になります。 jump._coyoteLeft のように外から読もうとすると、コンパイルエラーになります。

また、_coyoteLeft のように名前の先頭に _ を付けるのは、「これは private なフィールドです」という プログラマーどうしの慣習です（PascalCase・camelCase の慣習は第 2 回）。コンパイラが強制するものではありませんが、 プロパティ（大文字始まり・_ なし）と見分けやすくなります。

2.4 数値の暗黙の型変換（広がる変換と狭まる変換）

else _coyoteLeft = Math.Max(0, _coyoteLeft - dt);

Math.Max は、2 つの引数が同じ型であることを期待します。ここでは 0（int の整数リテラル）と、 _coyoteLeft - dt（float）を渡しています。型がちがうのにエラーにならないのは、 int の 0 が自動的に float に変換されるからです。これを広がる変換（widening）といい、 値の大きさが変わらない（情報が失われない）ので、C# は黙って変換してくれます。

逆に、float から int のように狭まる変換（narrowing）は、小数点以下が消えるなど情報が失われる可能性があるので、 自分で (int) のようにキャストを書かないとコンパイルエラーになります。実際に試すと、次のようになります。 

float f = 3.9f;
int n = f;   // エラー: CS0266 Cannot implicitly convert type 'float' to 'int'
C との違い: C では int n = f; と書いても、警告が出るだけでコンパイルは通り、小数点以下が切り捨てられて実行できてしまいます。 C# では狭まる変換をコンパイルエラーにするので、キャストの書き忘れにその場で気づけます。

これまでに出たもの: public（第 1 回）、float・f サフィックス（第 4 回）、 bool・PascalCase/camelCase の命名（第 2 回）。 C と同じもの: if・else、||・&&・!、比較演算子、// のコメント。

3. 計算式とアルゴリズムのポイント

3.1 タイマーを減らす（Update）

if (Grounded) _coyoteLeft = CoyoteSeconds;
else _coyoteLeft = Math.Max(0, _coyoteLeft - dt);

接地しているあいだは、毎フレーム _coyoteLeft を満タン（CoyoteSeconds）にリセットし続けます。 接地していなければ、毎フレーム dt だけ減らします。Math.Max(0, …) を挟んでいるのは、 タイマーが 0 より下（マイナス）にならないようにするためです。この考え方の図は くわしい解説の 3 節にあります。

3.2 猶予でジャンプを許可する（TryJump）

bool ok = Grounded || (useCoyote && _coyoteLeft > 0);
if (!jumpPressedEdge || !ok) return false;
  • ok は「接地している」か「猶予機能が有効で、かつ猶予がまだ残っている」のどちらかで真になります。
  • 次の行は、ジャンプを押した瞬間でない、または ok でないときに、早めに false を返す書き方です（ガード節）。両方の条件をくぐり抜けたときだけ、下のジャンプ成立の処理に進みます。

3.3 落とし穴: > 0 を >= 0 にすると

_coyoteLeft > 0 を _coyoteLeft >= 0 に変えるとどうなるか、実際に試しました。 Math.Max(0, …) のおかげで、タイマーは 0 未満にはならず、猶予が切れたあとはずっと ちょうど 0 のままになります。 >= 0 だと、ちょうど 0 でも条件が真になってしまうので、猶予が切れたあとも永遠にジャンプできてしまいます。 

bool ok = Grounded || _coyoteLeft >= 0;  // わざと >= にしたバグ版

接地せず 0.05 秒おきに 6 フレーム、毎回ジャンプを押した結果です。

frame 1: jumped=True
frame 2: jumped=True
frame 3: jumped=True
frame 4: jumped=True
frame 5: jumped=True
frame 6: jumped=True

猶予（0.12 秒）はとっくに切れているのに、6 フレーム目まで毎回ジャンプが成功してしまっています。等号を付けるかどうかの違いだけで、ここまで結果が変わります。

4. 呼び出してみる（Main と出力）

サンプルには実行の入口がないので、次のようなファイルを足して動かします。まず接地させてタイマーを満タンにし、 足場を離れたことにして、0.05 秒間隔で 3 フレーム進めます。1 フレーム目と 3 フレーム目でジャンプを押します。 

using System;

public static class Program
{
    public static void Main()
    {
        CoyoteJump jump = new CoyoteJump();
        jump.Grounded = true;
        jump.Update(0.016f);    // 接地中：タイマーは満タンのまま
        jump.Grounded = false;  // 足場から出た

        for (int frame = 1; frame <= 3; frame++)
        {
            jump.Update(0.05f);
            bool pressed = (frame == 1) || (frame == 3);
            bool jumped = jump.TryJump(pressed, true);
            Console.WriteLine("frame " + frame + ": jumped=" + jumped);
        }
    }
}

実行結果:

frame 1: jumped=True
frame 2: jumped=False
frame 3: jumped=False
  • 1 フレーム目は、足場を離れてから 0.05 秒しか経っておらず、猶予（0.12 秒）がまだ残っているのでジャンプは成功します。
  • 2 フレーム目はジャンプを押していない（pressed = false）ので、そもそも判定に進みません。
  • 3 フレーム目は、合計 0.1 秒経ってタイマーが 0 になっているので、同じようにボタンを押しても失敗します。
  • true・false を文字列と + でつなぐと、"True"・"False"（先頭大文字）になります。

5. まとめと、やってみよう

この回で出てきた C# の文法です。後の回では、ここへのリンクだけを置きます。

文法ひとことでC では
{ get; set; }自動実装プロパティ。フィールドのように読み書きでき、初期値も書ける構造体メンバー ＋ 別々のゲッター・セッター関数
フィールドとプロパティ外からは同じに見えるが、プロパティは実際には関数呼び出し構造体メンバーだけ
アクセス修飾子の省略何も書かなければ private（private の概念が無い）
_ で始まる名前private なフィールドの慣習的な印—
広がる変換・狭まる変換小さい型→大きい型は自動。大きい型→小さい型はキャストが要るどちらも警告だけで通ってしまう

やってみよう

  1. Math.Max(0, _coyoteLeft - dt) の 0 を 0f に書き換えて、結果が変わらないことを確かめる（もともと float に変換されているので同じになるはず）。
  2. _coyoteLeft > 0 を _coyoteLeft >= 0 に変え、3.3 節の実験を自分の手元でも動かして、同じ結果になることを確かめる。

確かめよう

問 1. float _coyoteLeft; には public も private も書かれていません。それでも外のクラスから読めないのはなぜ？

アクセス修飾子を省略すると、自動的に private になるからです。

問 2. Math.Max(0, _coyoteLeft - dt) の 0 は何型に変換されて渡される？ キャストを書かなくてよいのはなぜ？

float に変換されます。int から float は広がる変換で、値が失われないので、C# が自動でやってくれるからです。

問 3. CoyoteSeconds と _coyoteLeft は、どちらもクラスの中に値を持っていますが、書き方に違いがあります。何が違う？

CoyoteSeconds は自動実装プロパティ（{ get; set; }）で、外から読み書きでき、初期値も書けます。_coyoteLeft はただのフィールドで、修飾子が無いので private です。
