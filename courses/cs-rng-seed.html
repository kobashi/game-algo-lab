1. このコードがすること

このファイルには、同じ「次の 1 個の乱数を返す」という役目を、3 通りのやり方で実装したクラスがあります。

  • IUnitRng: 「NextDouble() を持つ」という約束（インターフェース）。
  • Mulberry32: サイトのデモが標準で使っている PRNG。
  • XorShift32: ビットシフトと XOR だけで作る PRNG。
  • Lcg: 線形合同法。教材用に、周期（同じ状態に戻るまでの長さ）を測る MeasurePeriod も持っています。

3 つのクラスはどれも IUnitRng を実装しているので、呼び出す側は中身のアルゴリズムを気にせず、同じ NextDouble() で使えます。 PRNG・シード・周期そのものの考え方はくわしい解説にあります。ここでは、コードとの対応に集中します。

2. 新しく出てくる C# の文法

2.1 interface と実装（: IUnitRng）

public interface IUnitRng
{
    /// <summary>[0, 1) の次の値</summary>
    double NextDouble();
}

interface は、中身を持たない「約束」だけの型です。ここでは「NextDouble() という、引数無しで double を返すメソッドを持つ」という約束をしています。 

public sealed class Mulberry32 : IUnitRng

class Mulberry32 : IUnitRng は「Mulberry32 は IUnitRng の約束を守ります」という宣言です。 約束したメソッド（NextDouble）を書き忘れると、コンパイルエラーになります。 XorShift32・Lcg も同じ約束を実装しているので、3 つとも IUnitRng 型の変数に代入できます。

C（関数ポインタで約束を表す）

/* 「1 つの関数を持つ」という約束を、関数ポインタの型で表す */
typedef double (*NextDoubleFn)(void *self);

C#（interface で約束を表す）

public interface IUnitRng
{
    /// <summary>[0, 1) の次の値</summary>
    double NextDouble();
}

C では、関数ポインタを構造体に持たせて、実装ごとに違う関数を差し込む、という書き方で近いことをします。 C# の interface は、この「差し込み口」を型として言語がチェックしてくれるものです。

2.2 uint・ulong と u サフィックス、16 進リテラル

uint a = _state;
a += 0x6D2B79F5u;

uint は符号なし 32 ビット整数、ulong（Lcg クラスで使用）は符号なし 64 ビット整数です。 0x6D2B79F5u のような 16 進リテラルと u サフィックスの書き方自体は C と同じです。

C

unsigned int a = state;   /* 大きさは環境しだい */
a += 0x6D2B79F5u;

C#

uint a = _state;
a += 0x6D2B79F5u;

C との違いは大きさの決まり方です。C の unsigned int・unsigned long は、何ビットになるかが処理系によって変わります。 C# の uint は必ず 32 ビット、ulong は必ず 64 ビットと決まっています。

2.3 符号なしの >> とオーバーフローの折り返し

uint t = (a ^ (a >> 15)) * (1u | a);

uint のような符号なしの型を右へ >> すると、空いた上位ビットには必ず 0 が入ります（論理シフト）。これは C の符号なし整数と同じです。

2.2 の a += 0x6D2B79F5u; は、_state の値によっては uint の最大値（約 42 億）を超えます。 C# はこれをエラーにせず、32 ビットに収まるように黙って折り返します（既定の設定が unchecked と呼ばれる動作です）。 実際に uint x = uint.MaxValue; x += 1; とすると、x は 0 になります（ただし uint.MaxValue + 1 のように定数どうしで計算すると、コンパイル時にあふれが分かるのでエラーになります）。 C でも符号なし整数の足し算は同じように折り返しますが、C の符号あり整数（int など）の桁あふれは未定義動作です。 C# では int のような符号あり型でも、既定では例外を出さずに折り返します。

2.4 条件演算子 ?:

public Mulberry32(uint seed) => _state = seed == 0 ? 1u : seed;

条件 ? A : B は C と同じ書き方です（条件が真なら A、偽なら B）。ここでは「シードが 0 なら 1 に置き換え、そうでなければそのまま使う」という初期化を、 式形式コンストラクタ（=>、第 3 回）1 行で書いています。

2.5 既定値付き引数

public XorShift32(uint seed, int a = 13, int b = 17, int c = 5)

引数に = 13 のように既定値を書いておくと、呼び出すときにその引数を省略でき、省略すると既定値が使われます。

C（既定値が無いので、別の関数を用意する）

XorShift32 xorshift32_new_full(unsigned seed, int a, int b, int c);
XorShift32 xorshift32_new(unsigned seed) {
    return xorshift32_new_full(seed, 13, 17, 5);
}

C#（1 つのコンストラクタで両方できる）

new XorShift32(seed);              // a=13, b=17, c=5
new XorShift32(seed, 6, 21, 7);    // 3 つとも指定

C には既定値付き引数が無いので、引数の少ないバージョンがほしければ、別の関数を書くか、呼ぶ側で毎回すべての値を渡す必要があります。

2.6 throw と例外・nameof

if (m < 2) throw new ArgumentOutOfRangeException(nameof(m));

条件がおかしいとき、C ではエラーコードを返したり exit で止めたりしますが、C# では throw で例外を投げます。 例外を投げると、そこで関数の実行が止まり、呼び出し元へ「異常があった」ことが伝わります（受け止める catch の書き方は入門コースでは扱いません）。

nameof(m) は、引数 m という名前そのものを文字列 "m" に変えるものです。 "m" と直接書くのと違い、引数名を変更したときにコンパイラがいっしょに直してくれます（綴りのずれが起きません）。

確かめた例: new Lcg(0, 1, 1, 1)（m = 1 < 2）を実行すると、次のように止まります。 
Unhandled exception. System.ArgumentOutOfRangeException: Specified argument was out of the range of valid values. (Parameter 'm')
   at Lcg..ctor(UInt64 seed, UInt64 a, UInt64 c, UInt64 m)
(Parameter 'm') の 'm' が、まさに nameof(m) で渡した文字列です。

2.7 (double) キャストと完全修飾名

return _x / (double)_m;

(double) は C と同じ明示的なキャストです。_x・_m はどちらも ulong（整数）なので、 先に (double) を付けないと _x / _m は整数の割り算になり、小数部分が消えてしまいます。 

var seen = new System.Collections.Generic.Dictionary<ulong, int>();

Dictionary<TKey, TValue> 自体は第 9 回で出てきましたが、このファイルの先頭には using System; しかありません。using System.Collections.Generic; を足す代わりに、名前空間を全部つなげた System.Collections.Generic.Dictionary（完全修飾名）をそのまま書くこともできます。

これまでに出たもの: 式形式メンバー =>（第 3 回）、 var・readonly・Dictionary<TKey, TValue>（第 9 回）、 TryGetValue と out（第 10 回。out int first のように型を書いても同じ意味です）。

C と同じもの: 16 進リテラルと u サフィックス、?:、(double) キャスト、符号なしの >>・^（XOR）・<<、for。

3. 計算式とアルゴリズムのポイント

PRNG・シード・周期の考え方そのものはくわしい解説にあります。ここでは、その式がコードのどこに対応するかを見ます。

3.1 LCG（線形合同法）

_x = (_a * _x + _c) % _m;
return _x / (double)_m;

式で書くと X' = (a·X + c) mod m、そのあと u = X' / m です。 % が「mod（割った余り）」、_x / (double)_m が [0, 1) への変換にあたります。 コンストラクタの _x = seed % m; で、シードもあらかじめ 0〜m−1 の範囲に収めています。

3.2 XorShift32

x ^= x << _a;
x ^= x >> _b;
x ^= x << _c;
_x = x;
return x / 4294967296.0;

シフトの向きと量（既定は 13・17・5）を変えながら、シフトした値と元の値を XOR することを 3 回繰り返します。 最後に 4294967296.0（232）で割って [0, 1) にします。uint の最大値より少しだけ大きい数で割ることで、割り算の結果が 1 になることはありません。

コンストラクタの _x = seed == 0 ? 0x9E3779B9u : seed; にも注目してください。シード 0 は「0 と 0 を XOR しても 0 のまま」という退化した状態なので、 あらかじめ別の値にずらしています。

3.3 Mulberry32

uint a = _state;
a += 0x6D2B79F5u;
_state = a;
uint t = (a ^ (a >> 15)) * (1u | a);
t = (t + ((t ^ (t >> 7)) * (61u | t))) ^ t;
return (t ^ (t >> 14)) / 4294967296.0;

状態 _state に決まった定数を足してから、シフトと XOR、掛け算を組み合わせて値を混ぜ（スクランブルし）ます。 最後にやはり 4294967296.0 で割って [0, 1) にします。式の意味そのものより、「毎回 _state を進めてから混ぜて返す」という流れをコードで追えれば十分です。

3.4 周期の測り方（MeasurePeriod）

var seen = new System.Collections.Generic.Dictionary<ulong, int>();
seen[x] = 0;
for (int i = 1; i <= maxScan; i++)
{
    x = (a * x + c) % m;
    if (seen.TryGetValue(x, out int first))
        return i - first;
    seen[x] = i;
}
return -1;

「何回目にその状態が出たか」を Dictionary<ulong, int> に記録しながら、LCG の式を maxScan 回まで進めます。 以前に見た状態ともう一度出会ったら、そのときの回数の差が周期です。maxScan 回進めても出会わなければ -1 を返します （m がとても大きいと現実的な回数では出会えないので、教材用の小さな m でだけ使う関数です）。

落とし穴: _x / (double)_m のように、割り算の前にキャストする必要があります。 (double)(_x / _m) のように割り算の後にキャストすると、_x / _m が先に整数の割り算として計算されてしまい、 小数部分が失われます。実際に x=7, m=5 で試すと、x / (double)m は 1.4 ですが、(double)(x / m) は 1 になります。

4. 呼び出してみる（Main と出力）

using System;

public static class Program
{
    public static void Main()
    {
        IUnitRng rng = new Mulberry32(42);
        for (int i = 0; i < 4; i++)
        {
            Console.WriteLine(Math.Round(rng.NextDouble(), 4));
        }

        var withDefaults = new XorShift32(123456789);
        var withCustom = new XorShift32(123456789, 6, 21, 7);
        Console.WriteLine("XorShift32 既定(13,17,5): " + Math.Round(withDefaults.NextDouble(), 4));
        Console.WriteLine("XorShift32 変更(6,21,7): " + Math.Round(withCustom.NextDouble(), 4));
    }
}

実行結果:

0.6011
0.4483
0.8525
0.6697
XorShift32 既定(13,17,5): 0.6321
XorShift32 変更(6,21,7): 0.0232
  • IUnitRng rng = new Mulberry32(42); のように、変数の型を interface にして、実際の中身に Mulberry32 を入れています。デモの標準 PRNG（Mulberry32、シード 42）と同じ、0.6011, 0.4483, 0.8525, 0.6697 … という列になります。
  • 同じシード 123456789 でも、XorShift32 のシフト量（a・b・c）を既定の 13・17・5 から 6・21・7 に変えると、まったく違う値になります。既定値付き引数のおかげで、両方とも同じコンストラクタで作れています。

5. まとめと、やってみよう

この回で出てきた C# の文法です。後の回では、ここへのリンクだけを置きます。

文法ひとことでC では
interface「このメソッドを持つ」という約束の型関数ポインタで代用
uint・ulong大きさが必ず 32/64 ビットの符号なし整数大きさは処理系しだい
符号なしの >>・オーバーフロー右シフトは 0 埋め。桁あふれは既定で折り返す（unchecked）符号なしは同じ。符号ありの桁あふれは未定義動作
?:条件演算子同じ
既定値付き引数int a = 13 のように省略時の値を書く無い（別関数を書く）
throw・nameof例外を投げる／引数名を文字列にする戻り値やコード、exit で代用
完全修飾名using の代わりに名前空間をすべて書く—

やってみよう

  1. 4 節の Mulberry32(42) のシードを 43 に変えて、出てくる 4 個の値が変わることを確かめる。
  2. XorShift32 のシフト量を、既定の (13, 17, 5) のまま 2 個作って、同じシードなら同じ値になることを確かめる。

確かめよう

問 1. Mulberry32・XorShift32・Lcg の 3 つが同じ IUnitRng 型の変数に代入できるのはなぜ？

3 つとも interface IUnitRng を実装している（: IUnitRng と書き、NextDouble() を持っている）からです。

問 2. new XorShift32(seed) のように 1 個だけ引数を渡すと、a・b・c はどうなる？

既定値の 13・17・5 になります。既定値付き引数なので、省略した分は宣言に書かれた値が使われます。

問 3. _x / _m を先に計算してから (double) でキャストすると、なぜまずい？

_x・_m がどちらも整数（ulong）なので、キャストする前に整数の割り算が行われ、小数部分が失われてしまうからです。
